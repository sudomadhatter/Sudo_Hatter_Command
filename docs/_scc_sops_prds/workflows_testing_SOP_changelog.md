# The Sudo Dev System — changelog

**One line per change: date · ticket · what changed for the operator.** Newest first.

This file is where the change story lives, so that
[`workflows_testing_SOP.md`](workflows_testing_SOP.md) can state the *current* system in present
tense with no "since SCC-x" narration — the writing contract is
[`sop-currency.md`](../../.agents/rules/sop-currency.md) §Writing the update, habit 4. When the
SOP-currency gate makes you update the SOP, the delta description goes **here**, as one line, in
the same commit. Deeper history: `git log --follow` on the SOP, and the per-ticket session folders
under `_artifacts/_main/`.

The entries below were harvested from the SOP's own body during the 2026-08-21 de-clutter. A date
of `—` means the page recorded the ticket but not the day; the ticket's session folder under
`_artifacts/_main/` or the Jira board has the full record.

| 2026-09-12 | SCC-452 | **The review you are asked for is sized by blast radius now, not by how many lines you changed.** `tiny` — "the plan is two sentences" — used to mean fifty lines and five files, which cannot tell a three-line edit to a module forty files import from a forty-line edit to a leaf nobody imports. The tier reads `code-review-graph impact` and forces `quick` when more than ten other files reach what you touched. It moves in one direction only: where there is no measurement — no graph built, or a language the graph has a known blind spot in, which is most Python and TypeScript zeros — the line count decides exactly as before, so an absent graph costs you a `quick` review you may not have needed and never a skipped one. `code-review-graph update --repo <r>` buys the sharper answer. The cap was measured rather than picked: the distribution's knee sits at ten in both repos that carry a graph. Router entry points stay refused outright, because `app/layout.tsx` wraps every screen and nothing imports it — a score alone would call the riskiest file in the tree the safest. |
