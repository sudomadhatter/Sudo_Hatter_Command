**Evaluated 2026-08-22:** `base` (basemode, Rust, single author, repo created 2026-06-02, 18 stars, v0.13.0→0.13.2 cut within 31 min on 2026-08-21) is NOT a GitNexus replacement.

- **License is identical** — both are PolyForm Noncommercial 1.0.0 (verified: `gitnexus` package.json + base `LICENSE.md`). Developing a paid product (AGY) with either is commercial use. GitNexus sells a commercial license (`founders@akonlabs.com`, Akonlabs enterprise); base says "separate commercial license granted individually".
- **Different tool** — base is a memory/handoff/task graph (SPARQL over NQuads in `.base/`) with hooks that inject context every prompt. Its code map (`base ast query`) answers only name-contains / file-entities / direct callers / importers. No transitive `impact`, no `detect_changes`, no `pdg_query`/`explain`, no `trace`, no `rename`. Those are the four things `docs/gitnexus.md` and the cicd gates actually call.
- **No MCP server** — hook-only. Claude Code today; Codex/Antigravity adapters exist but README says "coming soon"; opencode needs a JS plugin shim still "in development". GitNexus is MCP and serves all four platforms.
- **Same staleness problem, worse plumbing** — its AST map is machine-local too (`.base-ast/`, self-gitignored) and refreshes via `.git/hooks/post-checkout`, which is INERT here because `core.hooksPath=.githooks` ([[git-hooks-live-in-githooks-not-git-hooks]]). Extractor is Python (`scripts/ast/extractor.py` + 27 tree-sitter wheels); `base install` runs `python -m pip` — the Mac has only `python3` and no `tree_sitter` ([[two-machines-mac-and-pc]]).
- **Install footprint** — writes 4 user-level hooks into `~/.claude/settings.json` (fires in every repo), appends a "MANDATORY FIRST TOOL: ALWAYS use base ast query BEFORE grep/Read/any MCP tool" block to `~/.claude/CLAUDE.md` (collides with AGENTS.md-as-single-source), and silently self-updates from GitHub releases at SessionStart.

**How to apply:** Do not re-evaluate base for code intelligence. If the driver is the license, the two real options are a GitNexus commercial license (zero migration) or an MIT code-graph MCP. Evaluated 2026-08-22 against AGY's needs (508 py / 164 tsx / 75 ts; `impact` + `detect_changes` + `context` contract in `docs/gitnexus.md`; 4 platforms; Mac arm64 + Windows):
- **codebase-memory-mcp** (DeusData, MIT, 39.9k★, v0.10.8) — FIRST PICK. Single static binary (darwin-arm64 + windows-amd64, no runtime → kills the PATH/shebang/python-vs-python3 traps), LSP-grade type resolution for Python + TS/TSX, `detect_changes` (git diff → blast radius + risk) + `trace_path` + `query_graph` (Cypher), background watcher, optional committable `.codebase-memory/graph.db.zst` snapshot (the index can finally travel between machines). Risk: 478 open issues, one maintainer (1346 of ~1500 commits); Antigravity not named in docs (stdio MCP via `.antigravity/mcp.json` should work like gitnexus did).
- **code-review-graph** (tirth8205, MIT, 30.7k★, v2.3.8, PyPI) — RUNNER-UP. 30 tools that map almost 1:1 onto GitNexus names (`detect_changes_tool`, `get_impact_radius_tool`, `list_flows`, `list_communities`, `list_repos`, `cross_repo_search`), indexes `git ls-files` only (no submodule swallowing, no `.gitnexusignore`), explicit `--platform antigravity|opencode|codex|gemini-cli`. Risk: Python 3.10+ runtime on both machines (fastmcp ≥3.2.4 + PYTHONUTF8 on Windows), tree-sitter heuristic call resolution, flow recall 33%.
- **CodeGraphContext** (MIT, 4.1k★) — ranked below both: no diff-based change detection, no impact radius, different embedded DB per OS (FalkorDB Lite on Unix vs Kuzu on Windows). **Serena** (MIT, 28k★, LSP) — precise refs but no graph/impact/detect_changes; not a GitNexus replacement on its own.
Deciding test before any swap: index AGY with the top pick, run `detect_changes` on a recent story diff and impact on `calculate_cognitive_zone` (known HIGH, 7 upstream callers), compare against GitNexus's answers. Every GitNexus dependency in the toolkit is soft ("if indexed", check-9 nag only), so the swap is 4 MCP configs + 6 skill files + `docs/gitnexus.md` per repo. Related: [[gitnexus-index-not-actually-live]].

**Re-weighted 2026-08-22 (operator: "the one that helps the most with code reviews and self audits, and helps the agent use my rules and skills, fitting my folder structure"):**
- **Code graph → code-review-graph first.** Built for the review loop: `detect_changes_tool` (working diff → risk-scored functions, impacted flows, test gaps, review questions), `get_review_context_tool` (minimal file set + call chains), `get_affected_flows`, `get_impact_radius`, `get_knowledge_gaps`, `get_hub_nodes`/`get_bridge_nodes`, ships `review-changes`/`review-delta`/`review-pr`/`refactor-safely` skills. Indexes `git ls-files` (tracked dot-dirs like `.agents/` INCLUDED — GitNexus was blind there; submodules excluded unless `CRG_RECURSE_SUBMODULES=1`), Markdown indexed as doc-section nodes. Per-worktree `.code-review-graph/` SQLite (gitignore it; `CRG_DATA_DIR` to externalize), user-level registry `~/.code-review-graph/registry.json`, project-level installs. Caveat: Python 3.10+ on both machines; tree-sitter heuristic call resolution. codebase-memory-mcp stays the precision/plumbing runner-up.
- **Rules/skills layer → no product; native mechanisms fit the three-layer plan exactly.** Claude Code: `.claude/rules/*.md` with `paths:` frontmatter loads ONLY when a matching file is read (symlinks allowed → link the path-shaped on-demand masters from `.agents/rules/`; rules WITHOUT `paths:` preload at launch, so never link the whole dir); `@AGENTS.md` import; `InstructionsLoaded` hook logs which rule loaded (a routing-canary probe). Antigravity: now defaults to **`.agents/rules/`** — the master dir itself — with Always-On / Manual / Model-Decision / Glob activation per file (12k-char cap). Intent-shaped triggers ("something is broken", "Jira comes up") need a UserPromptSubmit hook that reads `rules/INDEX.md` trigger text and injects "⛔ trigger fired → read rule X" — Claude Code both OSes, Gemini CLI; Codex hooks are experimental, off by default, not on Windows; opencode needs a plugin. `base` was the product doing this — rejected above.
