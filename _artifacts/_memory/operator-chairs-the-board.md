First live test of `/sudo-adviser-board` (2026-07-19), Daniel's feedback: the board "pushed a little too
hard to keep moving forward instead of letting the brainstorm grow"; teams should ask questions when they
lack context; "they are the minds im using they are not running the board meeting"; and "I dont need them
distracted with all the sudo / commands either... the workflow doesnt need to push the pace."

**Why:** Daniel knows his own toolkit and pipeline; the value of a brainstorm is depth and blind-spot
discovery, which dies when the facilitator drives toward convergence or advertises next process steps.

**How to apply:** in any multi-voice/facilitation command Claude designs or runs: (1) phases advance ONLY
on the operator's word — never suggest moving on or wrapping up; default next move is deeper into what's
on the table; (2) give voices an explicit ASK move — numbered questions to the operator when context is
missing, never invented facts; (3) zero mentions of other slash commands/workflows in session bodies —
the operator calls the next step. Baked into `/sudo-adviser-board` (§ The chair) 2026-07-19; apply the
same pattern to future party-mode-style commands. Related: [[wrapper-flows-collapse-nested-menus]],
[[daniel-sells-hormozi-style]].
