`docs/doc-graph.md` + `docs/doc-graph.json` are the **doc-to-doc wiring map of the `.agents/` toolkit** — "what references what" among rules/skills/commands. It's a DIFFERENT system from **GitNexus** (the code knowledge graph) and from `docs/repo-map.md` (folder/file structure). The `.md` (now ~170 lines) is the agent-facing summary (hubs, broken links, orphans); the `.json` is the machine dump. Generated by `.agents/scripts/generate_doc_graph.py`, default root `.agents/`, lobby-only, deterministic/no-LLM/~$0. Not part of the `/1_update-maps` flow (that only regenerates `repo-map.md`).

**Why it was stale since June 29 (found + fixed 2026-07-14):** a doc held an `https://firebase.google.com/...md` URL; the token regex grabbed the part after `https:` → `//firebase.google.com/...md`, and on Windows `Path(root) / '//host/...'` becomes a **UNC network path** whose `is_file()` **blocks ~30s on SMB** trying to reach the host. So every regen silently hung → nobody had rebuilt it in weeks → the committed graph was a stale 30k-line/12,492-bmad-ref artifact. Fix (commit 338b91c): `clean_target` drops `//host` targets; `_cached_is_file` never stats a UNC path + memoizes probes → regen went from multi-minute hang to **~0.5s**.

**Scope — what the doc-graph maps (same philosophy as GitNexus, different tool):** only the toolkit WE authored. BMAD's `bmad-*` skill packs (vendor: ~65-70 internal md each) are **collapsed to one summary node per pack** (root + doc count) — an agent sees the pack exists + its size, but internals aren't parsed/wired. Do NOT fully enumerate bmad (it made the graph 81% nodes / 94% edges vendor noise), and do NOT DELETE bmad awareness either (Daniel: "if this is for agents then we do need the bmad — those are things the agent needs to know about"). Most bmad is already gone from `.agents/` anyway (sync excludes `bmad-*` from the vendor).

**How to apply:**
- Rebuild after editing rules/commands: `python .agents/scripts/generate_doc_graph.py` (bare, default root `.agents/`; never widen `--root` past `.agents/`). It's fast now.
- This is distinct from the maps in [[gitnexus-index-not-actually-live]] (code graph, per-repo, `.gitnexusignore`-scoped) and from `repo-map.md`. Don't conflate them — Daniel's "we don't map bmad/_artifacts" guidance was originally about GitNexus code scope; the doc-graph SUMMARIZES bmad rather than dropping it.
- The generator is vendored to every project via `/sync-agents`; the UNC fix is now in all 8.
