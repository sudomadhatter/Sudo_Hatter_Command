Since 2026-08-09 (SCC-66) every command has **exactly one door per platform**, generated by
`sync-agents.ps1` from one body in `.agents/commands/`:

| Platform | Door |
|---|---|
| Claude | launcher `SKILL.md` in `.claude/skills/` (Claude publishes a slash command per SKILL.md) |
| Codex | the **same** launcher, read natively from `.agents/skills/` |
| opencode | command mirror in `.opencode/commands/` |
| Antigravity | the **same** launcher, read natively from `.agents/skills/` (SCC-394 — workflows retire 2026-11-01) |

**Why:** Codex structurally cannot expose repo-defined top-level `/name` commands — skills are its
only door — and Claude already publishes a slash command for every `SKILL.md`. So one launcher
serves both, and a command mirror beside it was always a *second* door. Both duplicates
(`.claude/commands`, `~/.codex/prompts`) are retired and purged by the sync.

**Rules that bite:**
- A `SKILL.md` **without** the `GENERATED by sync-agents` marker is hand-authored — never
  overwritten, never pruned. Add real content by hand-authoring; the generator steps aside.
- Placement is per-platform: `.agents/skills` is Codex-visible, so a **claude-only** command's
  launcher goes to the `.claude/skills` cache ONLY, and a **codex-only** launcher is kept OUT of
  that cache. A door in the wrong place is as wrong as a missing one.
- `platforms:` still governs reach; `claude`/`codex` in the list means *generate the launcher*,
  never *publish a command mirror*. See [[platforms-empty-list-means-nowhere]].
- Enforced by `tests/test_command_surfaces.py` (13 checks, in `run_all`), so drift fails a gate
  instead of being found by opening a menu.

Caches are per-machine — [[one-pc-windows-and-wsl]] — so a sync must run on each box, and
**Codex snapshots its skill catalog when a chat opens**: after a sync, start a new chat or the
menu looks unchanged. Related: [[command-center-sudo-skills]], [[codex-is-fourth-platform]].
