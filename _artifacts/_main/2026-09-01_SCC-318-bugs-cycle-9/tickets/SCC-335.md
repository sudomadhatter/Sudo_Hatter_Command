Why: Six `subprocess.run` calls reached `acli` with `text=True` and no `encoding=`, so they decoded with `locale.getencoding()`. `acli` is a Go binary and always writes UTF-8, so on any box whose locale is not UTF-8 every description read came back mojibake - and because `edit --description` REPLACES the whole field, a read-modify-write wrote the mojibake back. That is how SCC-318's own description was mangled on 2026-08-27, and `U+2B50` is LOSSY that way (UTF-8 `E2 AD 90`; cp1252 has no mapping for `0x90`). The ticket called it Windows-only; it is LOCALE-only, and `LC_ALL=C PYTHONUTF8=0` reproduces it on the Mac. Anchor: .agents/scripts/jira_feed.py, the `acli()` seam every verb rides.
