# SCC-211 — the production door pre-flights before it writes or gates

**Lane:** `chore/SCC-211-push-e2e-precheck` @ `fb5fb95` (origin/main) · worktree `.claude/worktrees/SCC-211-push-e2e-precheck`
**Ticket:** SCC-211 (Task, moved to In Progress) · **Sibling lanes:** SCC-235 touches only its own artifacts + `_artifacts/_memory/` — no overlap, no landing-order dependency.

## What is wrong, in one paragraph

`/cicd-push-e2e` is the only command that writes production `main`, and it is the only door that runs no
mechanical pre-flight: both siblings call a script (`closeout_preflight.py`, `task_preflight.py`) before
they touch anything; this one reads `git branch -a` and starts merging. A dirty epic checkout gets gated
dirty and merged clean — what ships was never tested. It also contradicts itself on the sign-off (line 13
says invoking it IS the sign-off; Step 4's mint comment demands separate verbatim words and says STOP),
and it admits `chore/*` branches at Step 1 with no rule for what they may do and no written procedure
after that line.

## The one decision — a SCRIPT, not inline bash (recommendation + the tradeoff)

The ticket's EDIT column prescribes three inline `git` lines in the door. I am building the pre-flight
as **`.agents/scripts/ship_preflight.py`** instead, invoked by one fenced line in the door, because:

- it is the pattern both sibling doors already use, and parity with them is the ticket's whole frame;
- it leaves an **exit code** the door STOPs on, not three outputs an agent reads and narrates past;
- it can be tested **behaviourally** in real temp repos (the same fixtures `task_preflight` uses), so the
  mutants acceptance row 5 demands are drawn from real decisions, not from markdown prose.

**The tradeoff:** one new usage surface (script + test file + `scripts/INDEX.md` row + SOP paragraph)
instead of a doc-only edit. The inline version would be testable only by pinning prose in the door, which
`prose-pinning-guards-are-vacuous` already records as weak evidence. If you would rather have the
doc-only version, say so and steps 2–3 below collapse to the three lines the ticket wrote.

### Step 2 — GREEN: `ship_preflight.py` (stdlib, imports `wf_common` + `task_preflight` helpers)

```
ship_preflight.py --repo PATH --branch B --expect-key KEY [--no-fetch] [--json]
```
All three flags **required** (`cwd is not intent` — the door has `PROJECT_ROOT` bound and the branch named). Checks, in order, through `wf.Report` (exit 0 clean · 1 warnings · 2 blocking), header line `== ship preflight - <branch> ==` printed first, `VERDICT:` line last:

1. **shape** — `^(epic|chore)/([A-Z][A-Z0-9]*-\d+)-(.+)$`. `claude/*` → ERROR naming `/cicd-close-story-merge-tree`; keyless `epic/<slug>` → ERROR *rename it to carry the epic's real key first; never invent one*; anything else → ERROR.
2. **intent** — key segment (upper) == `--expect-key` else ERROR `--expect-key X but <branch> carries Y`; key ∈ `task_preflight.repo_keys(repo)` (`.agents/jira.conf`) else ERROR.
3. **sync** — `git fetch` by default (`--no-fetch` → WARN + `stale` on the verdict, as `task_preflight` does since SCC-193); `origin/<branch>` must exist (ERROR `never pushed`); if a local branch exists, `rev-list --left-right --count origin/B...B` must be `0 0` (ERROR `N ahead / M behind`); `git -c core.quotepath=false status --porcelain` in `--repo` must be empty (ERROR `N uncommitted change(s) — the gate would run on a tree the merge does not carry`).
4. **lane** — `epic/` → INFO `full gate`. `chore/` → `task_preflight.deploy_surface(repo)` ∩ `git diff --name-only origin/main...origin/<branch>`: non-empty → INFO `deployable path(s): … — light gate applies here`; empty → ERROR `nothing deployable in this diff — Task work; STOP and hand it to /smh-close-task-merge-tree`. Reuses the SCC-118 list (`PRODUCT_DIRS` + `.github/` only where a product exists) by import, never re-typed.

It reads and prints; it never merges, fetches anything but refs, or writes a file. `--json` mirrors the siblings for harnesses.

> ⚠️ **AUDIT FINDING F3 (baked in):** the fetch runs with `GITHUB_TOKEN` removed from the child environment — the door's own Rule 2 (`cicd-push-e2e.md:26-27`) names a stale session token as a known fetch/push failure, and a failed fetch here would downgrade the sync check to `stale` instead of fresh. `wf.git` takes no env, so the fetch is the one call built with `subprocess.run(..., env=<os.environ minus GITHUB_TOKEN>)`.
