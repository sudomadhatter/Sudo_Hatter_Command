# SCC-63 — naming convention 2.0 · walkthrough

> **Status: SHIPPED TO BRANCH, NOT MERGED.** Execution stopped at the Phase 8 operator audit gate by
> design. Nothing has touched `main`; SCC-63 is still In Progress; the close-out has not run.

## 1. What this was

The `sudo-` command prefix carried no information — it was on the dev-loop commands, the command-centre
maintenance commands, and one incident-response command alike, so the name told you nothing about what a
command would *act on*. That matters because target-resolution law differs per family: a dev-loop command
must bind to exactly ONE project and never the lobby, while a centre command may act on the repo you are
standing in. The prefix is now that declaration.

**The law, as shipped:**

| Family | Meaning | Target-resolution |
|---|---|---|
| `cicd-` | the BMAD story/epic dev loop and its logistics | exactly ONE project, **never** the lobby |
| `smh-` | workflows run ON the command centre itself | may act on the repo you are standing in |
| `sentry-` | the Sentry incident system | its own system |

Hyphens only, no underscores. `_AP` robot-lane twins become `-AP`. Vendor BMAD bridges (20) and
knowledge skills keep their names — they are not ours to rename. Skills take no prefix.

## 3. The edits that were NOT cosmetic

A rename of this shape is mostly text, and the text is the least interesting part. These four would have
broken things silently:

1. **Four LIVE `_AP` regex filters in `sync-agents.ps1`** (lines 459, 524, 634, 781) select the headless
   robot-lane commands out of every human menu by matching `_AP\.md$`. Renaming the files to `-AP`
   without these would have leaked all three headless commands into all four platform menus — a working
   system that quietly offers you the wrong door.
2. **`closeout_preflight.py` now globs BOTH prefixes.** Historical story artifacts are named
   `sudo-code-review-<story>.md` and live in *project* trees, which this rename does not reach. Had the
   glob followed the rename, every historic story would resolve to "never reviewed" and go red.
3. **`workflow_lint.check_naming_law`** — new, and the reason the law does not rot. It errors on any
   command outside the three families and on any `_` in a command stem, with a 20-name `VENDOR_COMMANDS`
   allowlist. It ships with **negative controls**: fixtures that deliberately carry `sudo-code-review.md`
   and `autopilot_claude.md` and assert the check *rejects* them. A check that cannot fail proves nothing.
4. **`check_ap_twins` glob** `*_AP.md` → `*-AP.md`, and the `_RULE_POINTERS` entry for the renamed rule.

## 4. Four bugs found and fixed during execution

These are recorded because the same trap will be there for the per-repo passes in SCC-70.

1. **The sweep deleted a 40 KB authoring source.** `sync-agents.ps1` protects three hand-owned files in
   `.agents/workflows/` **by filename** (`$excluded`, line 518). I renamed the entries *inside* that list
   to the new names but never renamed the file on disk, so the very next sync no longer recognised
   `update-maps-indexes.md`, classified it as a stale mirror, and deleted it — 39,933 bytes of the real
   workflow (`commands/` holds only a 4 KB wrapper). Caught by reading the deleted-file sizes rather than
   trusting the sync's own summary. Restored, renamed properly, swept, and the hazard is now written into
   `.agents/workflows/INDEX.md` so the next person meets it as documentation instead of as data loss.
2. **`.ps1` filenames corrupted** in 8 places — the caveated sweep regex treated a path separator as a
   command slash and produced nonexistent `smh-sync-agents.ps1` / `smh-new-project.ps1`. The real script
   names never changed.
3. **Compound filenames corrupted** in 8 files — `code-review.md` → `code-smh-review.md`, which also
   broke a launcher path inside `.agents/skills/cicd-code-review/SKILL.md`.
4. **The sweep clobbered its own guards.** Re-running it over files already hand-edited collapsed the
   `closeout_preflight` back-compat glob to a single prefix and rewrote the negative-control fixtures so
   they no longer proved anything — both greens that would have lied. Restored, with comments at both
   sites explaining why the retired names there are deliberate.
