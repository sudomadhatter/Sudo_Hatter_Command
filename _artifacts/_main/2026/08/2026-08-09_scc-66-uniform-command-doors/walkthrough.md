# SCC-66 — one door per platform per command

Lane 3 of the agnostic-system program
([plan](../2026-08-09_agnostic-system-program/implementation_plan.md), approved 2026-08-09).

## What was wrong

The command surface was mixed, and the mix was invisible until a human opened a menu and found it
wrong — which is exactly how the failed session started (*"none of the other LLMs use commands,
only Claude… I have none of the `/` commands in Codex"*). Measured before touching anything:
55 command bodies · 19 `.claude/commands` mirrors · 14 hand-written launcher skills · at least 5
names carrying **both** a Claude command mirror and a skill · a deprecated `~/.codex/prompts`
cache sitting beside Codex's native skill door.

Two constraints make the answer forced rather than chosen: **Codex cannot expose repo-defined
top-level `/name` commands at all** — skills are its only door — and **Claude publishes a slash
command for every `SKILL.md`**, so a skill already *is* a Claude door and a command mirror beside
it is a second one. One launcher skill therefore serves both.

## Decisions

- **`platforms:` semantics extended, not replaced.** `claude`/`codex` in the list now means
  "generate the launcher for that surface", never "publish a command mirror". A command with a
  **hand-authored** skill may still declare `[opencode, antigravity]` (SCC-59's shape) — its skill
  already serves Claude + Codex, and the generator leaves it alone either way.
- **Retirement rides the existing manifest**, not a new delete path: claiming nothing makes the
  proven ownership purge do the work, so a file the sync never wrote still cannot be touched.

## Pitfalls

- **⛔ `-WhatIf` caught a destructive bug before it ran — twice.** `Get-SkillDirSet` returns
  `,@(...)` (the wrapper idiom that stops an empty/1-element array unrolling). Piping it into
  `Where-Object` — *and* wrapping the call in `@()` — both hand the pipeline the inner array as
  **one object**, so the manifest's `$now` list matched no name and the purge proposed deleting
  **all 32 skill dirs**, hand-authored ones included. Only a bare assignment unrolls that wrapper.
  The dry run is the reason this is a footnote instead of an incident.
- **⛔ `echo "$out"` truncates at `\c`.** Shell `echo` treats the `\c` inside `.claude\commands`
  as "stop output", so gate greps over captured sync output silently read a cut-off stream — it
  reported 0 Codex-prompt purges while the purge was working correctly. Same read-a-failure-as-a-pass
  family as `| tail` hiding an exit code. **Use `printf '%s\n' "$out"`.**
- **A UTF-8 BOM made 8 commands read as universal.** `PowerShell`'s `ReadAllLines` strips a BOM;
  Python's `utf-8` read leaves `﻿` on line 1 and `str.strip()` does **not** remove it (U+FEFF
  isn't Python whitespace), so the frontmatter probe missed and eight `platforms: [opencode]`
  testarch bridges looked universal — the test demanded Claude/Codex/Antigravity doors for them.
  Fixed with `utf-8-sig`. Two parsers of one file must agree byte-for-byte or the gate invents work.
