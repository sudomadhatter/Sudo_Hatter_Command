# Implementation Plan — Give `.agents/` its correct floor law (AGENTS.md + INDEX.md + adapters)

## Goal
`.agents/` is the master toolkit — the single source of authorship for every tool the agent has (rules,
commands, skills, workflows, bmad, scripts, templates, hooks). The workspace standard lists it as a **Tier-1
Floor** that must carry a full `AGENTS.md` + adapters, but it never had one — only a GitNexus stub, which the
other team deleted. This authors the **real** floor law so an agent entering `.agents/` immediately knows
what the folder is, how to act in it, and where each tool lives.

## Why (verified)
- The deleted `.agents/AGENTS.md` + `.agents/CLAUDE.md` contained **only** a GitNexus block — 0 lines of
  routing law (checked every git version; the one commit `8ffea7c` that ever touched them was pure block).
  Restoring them brings back a stub, not law.
- `docs/workspace-standard.md:77` lists `.agents/` as a **Tier-1 Floor** → should have "full `AGENTS.md`
  (Map/Mission/Support + routing table) + 1-line adapters." That gap is what we're closing.
- Toolkit inventory (ground truth): `rules/` (14, has INDEX), `commands/` (46, has INDEX), `skills/` (38, has
  INDEX), `workflows/` (20, has INDEX), `bmad/` (8, BMAD-owned), `scripts/` (8), `templates/` (1), `hooks/`
  (1), `opencode-agents/`. Four subfolders already have their own `INDEX.md`; the top level has neither
  `AGENTS.md` nor `INDEX.md`.

## Files to create (4)

### 1. `.agents/AGENTS.md` — the Tier-1 floor law (~35 lines)
The "how to act in the toolkit" brain. Sections:
- **§1 ROOT LAW** — this is THE master toolkit, the single source of authorship for the whole system; every
  tool originates here. Vendored copies (`.claude/`, `.opencode/`, each `Projects/<name>/.agents/`) are
  downstream — **never edit those; edit here, then `/sync-agents`.**
- **§2 START HERE / reading-order** — don't read the whole toolkit; jump via §3 to the right subfolder and
  scan its `INDEX.md`. (Mirrors the lobby's reading-order rule.)
- **§3 ROUTING TABLE** (task → subfolder → its INDEX) — the core:
  behavioral law → `rules/` (`rules/INDEX.md`); slash commands → `commands/` (`commands/INDEX.md`);
  capabilities → `skills/` (`skills/INDEX.md`); Antigravity mirror + reference → `workflows/`
  (`workflows/INDEX.md`); BMAD install → `bmad/` (**owned — regenerated by BMAD, never hand-edit**);
  maintenance scripts → `scripts/` (check_maps · generate_repo_map · record_map_changes · sync-agents);
  scaffold → `templates/project-template/`; git-approval hook → `hooks/`; opencode agents → `opencode-agents/`.
- **§4 THE LAW** — single source of authorship; `/sync-agents` mirrors to all three platforms; `platforms:`
  frontmatter limits reach; rules are read in-place (never copied to `.claude/rules`).
- **§5 GATES / GO BACK UP** — full gates → `constitution.md`; non-toolkit work → up to `../AGENTS.md` /
  `../router.md`.
- **No GitNexus block** (that's what the stub was). If we want graph routing later, a one-line pointer is
  enough — decided out of scope here to avoid re-creating the stub.

### 2. `.agents/INDEX.md` — the inventory (~20 lines)
The "what's in here" map: one row per subfolder → purpose → entry point (its `INDEX.md` where one exists) →
count. Points to the four existing sub-INDEXes rather than duplicating them.

### 3. `.agents/CLAUDE.md` + 4. `.agents/GEMINI.md` — bare 1-line adapters
"Read `AGENTS.md` in this same folder and follow it." Matching every other front door + our dedupe work.

## Edge cases / notes
- **Propagation:** `.agents/` contents are vendored into each `Projects/<name>/.agents/` by `/sync-agents`
  (additive robocopy), so this floor law will propagate to every project's toolkit copy on the next sync —
  desirable (same toolkit law everywhere). Front-door files at repo roots are NOT synced, but these live
  *inside* `.agents/`, so they ride along.
- **No GitNexus re-injection risk:** there's no `.gitnexus` runner inside `.agents/` (confirmed by the
  top-level listing), so `analyze` won't clobber the new `AGENTS.md`. If the machine-local SUDO_COMMAND index
  is ever re-run against `.agents/`, apply the same `skipAgentsMd` fix we used on the lobby/AGY.
- **Lobby-only for now:** authored at master `.agents/`; propagates to projects via `/sync-agents` when you
  choose to run it.
