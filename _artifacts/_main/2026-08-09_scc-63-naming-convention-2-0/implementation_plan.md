# SCC-63 — / naming convention 2.0 (sudo- retired → cicd- / smh- / sentry-)

## Goal and evidence

Rename the command surface so the prefix states what a command IS, forever: `cicd-*` = the BMAD-paired
story/epic dev loop and its logistics; `smh-*` (Sudo Mad Hatter) = workflows run ON the command center
and everyday operator tasks; `sentry-*` = the Sentry incident system, a separate system from the dev
loop. The `sudo-` prefix is fully RETIRED so any surviving `/sudo-` reference anywhere is provably
stale. Operator rulings (brainstorm 2026-08-09): two buckets for workflow commands plus the reserved
`sentry-` family; hyphens replace underscores in the same pass; autopilot launchers join the cicd
family; `scc-` was rejected (Jira-tag confusion); `/webm-alpha-video` is retired as a command and
becomes a skill (Phase 2b). Census evidence (2026-08-09, this session): 56 files in
`.agents/commands/` (26 ours incl. 3 `_AP` twins, 21 vendor BMAD bridges, rest INDEX/knowledge);
mirrors in `.opencode/commands/` (50), `.agents/workflows/` (29), `.claude/skills/` (106) are ALL
regenerated by sync; functional hardcoded names live in exactly 6 scripts + 7 test files + 1 hook
(listed in Phase 4). SCC-38 (workflow graph/ledger/CI) executes AFTER this lands so its permanent
artifacts are born with final names.

## Target architecture

```text
.agents/commands/<name>.md        = the brain (master). RENAMED here only.
.agents/skills/<name>/SKILL.md    = hand-authored skill masters. RENAMED here only.
.claude/skills/ .opencode/commands/ .agents/workflows/ + machine caches
                                  = doors. NEVER hand-edited; regenerated by sync-agents.ps1;
                                    .sync-manifest.json ghost-purges every retired name.
Naming law: cicd-<verb-phrase> | smh-<verb-phrase> | sentry-<verb-phrase>, hyphens only,
            _AP twin suffix becomes -AP.
            sentry-* is a THIRD family (operator ruling 2026-08-09), reserved for the Sentry
            incident system, which is a separate system from the dev loop. Today it has exactly
            one member; it exists so the incident pipeline's future commands have a home.
Vendor surfaces keep their names: bmad bridges (analyst, architect, bmad-help, bmad-master, dev, pm,
qa, sm, tea, tech-writer, testarch-*, ux-designer), firebase-* skills, knowledge packs (see table).
Brand names keep sudo: repo name, Projects/sudo-project-skeleton, sudo_workflows_testing.md filename.
```

## Phase 3b — Write the naming law down, then make it self-enforcing

A rename that lives only in this artifact is a one-time event; the next command minted six months
from now has nothing to obey. Record the law, then give it a machine.

1. **Root `AGENTS.md`** — beside the existing "one door per platform per command" section, state the
   three families in one short block: `cicd-*` = the BMAD-paired story/epic dev loop and its
   logistics · `smh-*` = workflows run ON the command center and everyday operator tasks ·
   `sentry-*` = the Sentry incident system (separate system, reserved family). Hyphens only, never
   underscores. An autopilot twin appends `-AP`. Vendor BMAD bridges keep their upstream names and
   take no prefix. Skills take no prefix — a prefix marks a command.
2. **`.agents/commands/INDEX.md`** — same law as a one-paragraph header above the table, plus the
   sentence that makes it greppable forever: *any `/sudo-` reference anywhere in this system is
   stale by definition.*
3. **`.agents/skills/INDEX.md`** — one line: skills carry no family prefix; a generated launcher
   inherits its command's name, a hand-authored skill is named for what it knows.
4. **Make it mechanical.** Add a check to `.agents/scripts/workflow_lint.py` under `--toolkit-only`:
   every `.agents/commands/*.md` basename must match `^(cicd|smh|sentry)-` OR appear in an explicit
   vendor allowlist — `INDEX`, `analyst`, `architect`, `bmad-help`, `bmad-master`, `dev`, `pm`, `qa`,
   `sm`, `tea`, `tech-writer`, `testarch-atdd`, `testarch-automate`, `testarch-ci`,
   `testarch-framework`, `testarch-nfr`, `testarch-test-design`, `testarch-test-review`,
   `testarch-trace`, `ux-designer`. Also fail on any `_` in a non-vendor basename. Add the matching
   positive AND negative fixtures to `.agents/scripts/tests/test_workflow_lint.py` (a negative
   control that a fake `sudo-thing.md` / `foo_bar.md` basename is REJECTED — a check that cannot
   fail proves nothing).
   ⛔ If this check cannot be made green without weakening it, STOP and report. Do not relax the
   pattern, do not widen the allowlist beyond the 20 names above, do not skip the negative control.
