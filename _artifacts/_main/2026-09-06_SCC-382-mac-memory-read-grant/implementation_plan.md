## The consequence first

On this Mac, Antigravity asks for approval every time it reads a Claude memory file, and the
permission battery says everything is fine. Both halves of that are the work.

SCC-387 built the machinery for a directory read grant and shipped exactly one row — the Ubuntu
machine's store, an absolute `/home/dlohn/...` path that matches nothing here. The Mac's row was

the SCC-393 failure shape repeating: a green battery over a fence with a hole in it.

audit measured it rather than argued it. v1 invented a skip tier the harness does not have. v2
replaced the derivation with an enumeration that cannot match from a worktree — which is where every
lane in this repo runs. Both are recorded below because the pattern is the finding: a guard that
reports green from the place it is actually run is worth less than no guard, and the road to it is
short.

### 1. The locator — resolve the MAIN checkout, not `ROOT`

⚠️ **AUDIT FINDING (v2, high, x2 — Lens 1 and Lens 3 independently, same anchor).** v2 said
*"keep entries whose `realpath` equals this repo's `_artifacts/_memory`"*, taking "this repo" to be
`ROOT = Path(__file__).resolve().parents[3]` (`test_permission_parity.py:37`). In a worktree that is
the **worktree** root, and `_artifacts/_memory` is tracked, so the worktree has its own real copy
while the `~/.claude` link points at the main checkout. Measured from this lane: **no candidate
matches**, so A15d takes its pass branch in every worktree — step 1's RED unobtainable, row B
unprovable, M1–M3 surviving for a reason unrelated to the fence, and the close-out gate
(`smh-close-task-merge-tree.md:260` runs `run_all.py` in the lane tree) certifying work it never
exercised.

```python
_HOME_ROOTS = ("Users", "home")

def _main_checkout() -> Path:
    """The MAIN checkout, stable from any worktree.

    `--git-common-dir` is `<main>/.git` in a worktree AND in the main checkout, so its
    parent is the one identity of "this repo" that does not move. ROOT does move:
    inside a worktree it is the worktree, whose own tracked `_artifacts/_memory` is a
    different inode from the one `~/.claude/projects/*/memory` links to (SCC-382 v2).
    """
    r = subprocess.run(["git", "-C", str(ROOT), "rev-parse", "--path-format=absolute",
                        "--git-common-dir"], capture_output=True, text=True)
    return Path(r.stdout.strip()).parent if r.returncode == 0 and r.stdout.strip() else ROOT

def _repo_stores(home: Path | None = None, root: Path | None = None) -> list[Path]:
    """Every `~/.claude/projects/*/memory` that IS this repo's memory store."""
    home = home or Path.home()
    wanted = {(p / "_artifacts" / "_memory").resolve()
              for p in ({root} if root else {_main_checkout(), ROOT})}
    return sorted(p for p in (home / ".claude" / "projects").glob("*/memory")
                  if p.exists() and p.resolve() in wanted)

def _grant_covers(granted: str, path: str) -> bool:
    """A recursive dir grant covers a path at or under it."""
    g = granted.rstrip("/")
    return path == g or path.startswith(g + "/")
```

`glob` silently drops the one broken link under `~/.claude/projects` (a `Fresh_Workspace_BMAD` store
whose target is gone); `p.exists()` makes that explicit rather than incidental.

### 3. ⚠️ AUDIT FINDING — `_covers`, without the tautology and without the crash

Three lenses converged. The v1 defect (Lens 3): `home = str(Path.home())` builds the sensitive tails
from the **running** machine's home, so each machine's grant is credential-checked only where it
lives and CI is blind to both. The v2 defect (Lens 1 **and** Lens 2, measured): "first two path
segments" makes the derived home a prefix of `granted` **by construction**, so every ≤2-segment grant
self-matches — `/opt/homebrew`, `/etc`, `/var/log` all flip `False → True`, a false credential-leak
report reddening the suite `main` gates on — and the indexed spelling raises **`IndexError`** on `/`,
`/Users` and `""`. `_harness.py` has no try/except and the raise happens while evaluating the
argument, so it escapes and takes blocks **B–H** down with it: 102 cases become a traceback. Today
`_covers("/", tail)` correctly returns `True`; the naive rewrite loses the check on the single most
catastrophic grant there is.

```python
def _covers(granted: str, secret_tail: str) -> bool:
    """Does this recursive dir grant reach a credential store, seen from ANY machine?

    The home is derived from the GRANTED string, never Path.home(): the fence carries one
    absolute row per machine, so a home-relative check inspects only the row belonging to
    the machine it runs on, and CI inspects neither (SCC-382). A grant not under
    /Users/<u> or /home/<u> is under no home at all - every SENSITIVE tail is
    home-relative, so there is nothing there for it to reach. `/` is answered first and
    literally: it covers everything, and no derivation would survive it.
    """
    if granted == "/":
        return True
    g = granted.rstrip("/")
    parts = [p for p in g.split("/") if p]
    if len(parts) < 2 or parts[0] not in _HOME_ROOTS:
        return False
    home = "/" + parts[0] + "/" + parts[1]
    return (home + secret_tail).startswith(g + "/")
```

Verified truth table (current → v3): `/` True→True · `<this home>` True→True (A16b keeps biting) ·
`/home/dlohn` False→**True** (the fix) · `/home/dlohn/.claude/projects/p/memory` False→False ·
`/opt/homebrew` False→False · `/etc` False→False · `/Users` False→False · `""` False→False. The old
`granted == home` clause is **deleted, not rewritten** — clause 3 already subsumes it, which is why
A16b is unaffected.

⚠️ **A16c must not hardcode a home the running machine uses (v2, medium).** If it pins `/home/dlohn`,
