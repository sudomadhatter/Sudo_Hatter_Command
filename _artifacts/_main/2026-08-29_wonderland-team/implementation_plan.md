## The idea, in one paragraph

Zoo Code ships five hard-coded modes that cannot be deleted — but a custom mode carrying the same
slug replaces the built-in **wholesale**, name included (verified against the v3.80.1 compiled
bundle: the merge in `getAllModes` swaps the entire mode object). So the operator's team takes the
five slots over and adds one: 🫖🐰 March Hare — TEAM LEAD on `orchestrator`, ⏰🐇 White Rabbit — PM
on `architect`, 🔨🪚 Carpenter — ENGINEER on `code`, ♥️👑 Queen of Hearts — QA on `ask`
(edit-stripped), 😼 Cheshire Cat — TESTER on `debug`, and 🦋 Caterpillar — DESIGNER on a new
`designer` slug. **Name law (operator correction, this session): the character name in regular
case, the ROLE in ALL CAPS after the em-dash.** The BMAD personas leave the mode picker (they stay reachable as commands/skills —
they are the cicd-flow workers); the picker becomes the operator's org chart. Everything is
generated by the SCC-349 sync machinery from masters in `.agents/` — nothing hand-edited in `.roo/`.

## Part A — Seat masters: one command file per seat

`NEW .agents/commands/team-march-hare.md · team-white-rabbit.md · team-carpenter.md ·
team-caterpillar.md · team-cheshire-cat.md · team-queen-of-hearts.md`

Each master carries, in the house command shape: the seat's **identity** (name WITH role, voice,
who it serves), its **doors** (the `/smh-*` and `/cicd-*` commands it runs and the skills it
bundles — CATERPILLAR: `emil-design-eng` + `apple-design` + the BMAD ux path; CHESHIRE CAT:
`/cicd-write-story-tests`, `/cicd-bdd-tests`, the `testarch-*` family; QUEEN OF HEARTS:
`/smh-code-review`, `/cicd-code-review`, self-audit — and a hard refusal to edit code; March Hare:
the full ceremony chain with ceiling = merge-ready, the operator lands every merge, and the
**delegation protocol**: it hands work to the other seats with Zoo's `new_task` tool — one subtask
per seat, `mode: <slug>` picked by reading each seat's `whenToUse`, results collected boomerang-style
— and may `switch_mode` when a conversation should continue in another seat; both confirmed present
in the v3.80.1 bundle (`new_task`, `switch_mode`, `alwaysAllowModeSwitch`, `alwaysAllowSubtasks`)), its
**refusals**, and the **routing law**: `/cicd-*` = the dev system pointed at real project work,
`/smh-*` = the same system turned inward on the command center. Frontmatter `platforms: [zoo]` —
one Zoo launcher door each in `.roo/commands/` and nothing on the other platforms (⚠️ AUDIT
FINDING baked in: the first cut said `platforms: []`, which `workflow_lint.py` rejects as an ERROR
— "syncs to NOWHERE"). Each new command gets its row in `.agents/commands/INDEX.md` (lint warns on
an unmentioned file).

- Assertion: each file exists, carries `platforms: [zoo]`, and names its doors; the QUEEN OF
