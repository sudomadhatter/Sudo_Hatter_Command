## What shipped

The 12,000-character Antigravity cap stopped being a rule anyone has to hold in their head.

`Sync-AntigravityWorkflowMirror` used to decide the shape of each door by **size**: over 11,500 bytes
it emitted a generated thin launcher, under it a verbatim copy of the command body. That conditional
is why the cap kept resurfacing three months after it was supposedly fixed — it was still an
**operative rule**, a number to measure against, and so it was restated in 39 generated door files,
8 script comments, 8 documentation sites and 7 memory entries. The branch is deleted. Every
antigravity-eligible command now emits the same few-hundred-byte launcher pointing at
`.agents/commands/<name>.md`, so no door can ever approach the cap and the number is unreachable by
construction rather than watched.

Rewriting one PowerShell string literal is what removed the cap sentence from all 39 doors at once.
The number now survives in exactly **one** operative place — the `-GlobalsOnly` section of
`/smh-sync-agents` — as the *reason* the launcher surface exists.

Dead code went with the branch, on both sides at once: `Set-AgDescriptionLine` in the engine, its
Python twin `with_ag_description`, and the two test blocks (`U6e`, `U8`) whose entire subject was
that pair. `Get-AgDescription` and the SCC-195 menu-description budget are **kept and still tested** —
that is a separate, still-live rule about the menu's *context*, not about body size.

## Three things the build found that the plan had wrong

**The count was 14, not 13.** Every naive sweep for verbatim doors said 13, and `CS-18 O` found the
fourteenth: `.agents/workflows/smh-sync-agents.md`. It carried the `GENERATED by sync-agents` marker
while being a full 10,352-byte body — because its *brain* documents that marker by name at line 21,
so the string was in the file for a completely unrelated reason. This is
`comment-literals-invert-source-grep-tests` one level up: not a comment inverting a grep, but a
document *about* a marker being mistaken for a file *carrying* it. `CS-18 O` classifies by
`is_launcher_for` and treats the marker only as a hint in its message, which is what caught it.

It is also the sharpest illustration of why the conditional had to go: that door sat **1,648
characters under the cap**. Fine that day. Truncated the week its command grew, silently, on the one
command whose job is to publish the doors.

**`$IsLobby` is TRUE in a worktree.** The plan's Step 7 said *"a worktree sync does not write the
machine-global caches"*, repeating a claim written into `CS-18`'s own commentary. Both were wrong:
`$HomeRoot` derives from `$PSScriptRoot` (`sync-agents.ps1:82-83`) and `$Target` defaults to it
(line 114), so a worktree compares equal to itself and a bare lane sync **writes this machine's live
Antigravity menu**. `-NoGlobals` is what keeps a lane sync local. Corrected in the comment that
taught it, with the consequence spelled out, because believing the false version is how a lane either
skips the sync it owes or fires one it did not intend.

**Two sibling guards were reading the wrong surface.** `test_live_testing_browser_instrument` asserted
that `.agents/workflows/cicd-live-testing-team.md` carried a substantial body routing to the
Playwright skill, and `test_zoo_notify` asserted a requirement sentence in
`.agents/workflows/smh-llm-approvals.md`. Both passed only because those two commands happened to sit
under 11.5 KB and so shipped verbatim — and both would have gone red the day either command grew,
with nothing connecting the failure to the edit that caused it. They now read the **opencode mirror**,
which is the surface that genuinely carries a second copy of the body (`Copy-Item -Force`, no launcher
form, no size rule), and each keeps a launcher-integrity check on the Antigravity door.

## Assertions — all seen RED before green

Written against unmodified source and run first. `CS-18 N` red because `11500` and
`Set-AgDescriptionLine` were still in the comment-stripped engine; `CS-18 O` red at **14 of 40** doors;
`CS-18 P` red at **38 of 662** swept files; the new door-parity control red because the verbatim arm
still returned `ok`.

| check | what it holds | why the old check could not |
|---|---|---|
| `CS-18 N` | the comment-stripped engine contains no cap number in any spelling, and no `Set-AgDescriptionLine` | keyed on `CAP_RE`, not the bare `11500` literal — a mutant that leaves the branch deleted but puts the cap sentence back in the **stub** re-publishes it to all 39 doors on the next sync without the threshold ever appearing (mutant M5) |
| `CS-18 O` | every door except `INDEX.md` and the hand-owned `smh-adviser-board.md` is a **current generated launcher** for its own brain | replaces `CS-18 B` (*"no door exceeds the cap"*), which was green through the entire defect and would have stayed green through this one: a verbatim door comfortably under the cap is exactly the shape that ships fine and truncates later |
| `CS-18 P` | the cap number survives only at one allow-listed site, swept across every tracked law, doc, door and memory file | inclusive detector with an explicit allow-list, so a mention in a comment **is** a site and fails — the polarity that a source-grep guard usually gets backwards |
| `CS-18 L` | the machine-global Antigravity cache is a **byte mirror** of `.agents/workflows/` | was *"no cached file exceeds the cap"*; the byte-mirror form also catches a stale machine, a hand-edit, and a cache fed from the wrong source — the SCC-332 defect itself, which the size test could not see |
| door-parity CONTROL | a byte-identical mirror is **not** legal on `.agents/workflows` | `door_verdict`'s byte-identity arm is now `not launcher_ok`; it was unconditional, which is why a verbatim Antigravity door read as parity for as long as the branch existed |

`CS-18 O0`, `O2`, `N0`, `P1`, `P2` and `P3` are the anti-vacuous controls: the hand-owned list parsed,
the sweeps read a real number of doors and files, the detector fires on every spelling and only those,
and the one allow-listed site still states the rule it is allow-listed for.

## Fixed in the lane, not billed

Four things this lane's own diff created or exposed, all closed here rather than reported:

- the false `$IsLobby` comment, corrected with its consequence
- the two sibling guards repointed at the body-carrying surface
- the hand-owned door's stated reason changed from **size** to **content** — `smh-adviser-board`'s
  launcher is not generated because it carries Antigravity-only INLINE-mode instructions the generator
  cannot produce, and a generated stub would silently drop them and run the board's parallel protocol
  with every spawn missing. The old reason ("19.8k body exceeds the 12k limit") stops being true the
  moment size stops selecting.
- eleven dead path claims in files this lane pulled into `check_links`' scope for the first time.
  Nine were prose false positives (cross-repo paths, a retirement row, an illustrative relative
  link); **two were real rot** — `docs/workspace-standard.md` claimed a `pr-check.yml` workflow the
  lobby does not have, and a memory linked three times to the GitNexus contract doc, deleted when GitNexus
  was retired. All eleven corrected in place; no gate exemption was added and no gate was weakened.

## Out of scope — named, not silently dropped

`sync-agents.ps1` exists in three other repos and **all three already differ** (82,223 bytes here
against 65,196 / 24,223 / 22,551). No copy receives this change, so it is not a port; the plan carries
a full six-check port section answering `port-checklist.md` with command output. Two of those repos
are deliberately unmaintained and all three would need their own Jira keys.

`.agents/scripts/INDEX.md:3` still describes `sync-agents.ps1` as *"Mirrored to project vendored
copies"*, retired by the thin model on 2026-08-07. Real staleness, about the **mirror policy** rather
than the launcher rule, so it is not fixed here.

## The one behaviour change, decided on the record

A launcher only resolves where `.agents/commands/` exists — the lobby. Seven of the ten folders under
`Projects/` carry zero `.agents/commands/*.md`, so the 14 commands that used to ship verbatim now
**STOP** rather than run when invoked from Antigravity's *global* menu inside a thin project.

Accepted, for three reasons in order of weight. It is the same trade already in force for the other
24 commands, so this makes one rule out of two. Twelve of the fourteen are lobby commands by design —
every `cicd-*` is a command-center→project door and every `smh-*` acts on the centre itself. And the
standard already argues this direction in its own words: *"A command that fails visibly beats one that
runs on 27% of its steps."* `sentry-security-team-avch` is the single genuinely project-scoped member;
if it ever bites, the fix is to run it from the lobby, not to restore the branch.
`docs/workspace-standard.md` was updated in the same commit so the written rule matches the built one.
