# SCC-416 — In-flight epic freezes main: refuse any main-bound lane whose diff overlaps a live epic branch

## Why

On 2026-09-05 Epic 24 work reached live production mid-epic. AVCH-80 (the rolling bug ticket) was cut as `chore/AVCH-80-rolling-bugs` off `main`; its riders AVCH-120/121/122 were Epic 24 findings routed out of story 24.4. Its diff overlapped the live `epic/AVCH-100-epic-24-agent-quality` in six files, three of them runtime (`backend/agents/specialist/agent.py`, `backend/agents/admin/agent.py`, `backend/tools/librarian.py`). `ship_preflight.py` classified the lane "chore touching backend → light gate → ship", `/cicd-push-e2e` opened PR #72 into `main`, it merged at `4afaa667`, and Cloud Run revision `aviationchat-backend-00076-boh` took 100% of traffic at 19:13:59 UTC. Not one Epic 24 story had been merged to `main`, by the operator's design.

The ruling forbidding this exists — the Epic 24 banner in `sprint-status.yaml`, operator ruling 2026-09-03: *"every story lands THERE, never on main… KEEP THE EPIC BRANCH CURRENT WITH main."* It lives on the epic branch, so a main-bound lane never reads it. The 2026-09-03 plan named the lobby-side guard as "Lane 2 — separate ticket, not started". This is that ticket.

Neither preflight looks at the live branch list. `ship_preflight.check_lane` and `task_preflight.check_scope` judge a `chore/*` lane by its own diff against `PRODUCT_DIRS` and nothing else; the production door's "every story on this epic must be done" check is switched off for the chore substitution. There is no mechanical check anywhere that asks "is this file being changed on a live epic branch?"

## Plan

- [ ] `task_preflight.py`: `live_epic_branches(repo)` (local + `origin/` epic refs) and `epic_overlap(repo, changed, base)` — the product-file intersection of a lane's diff with each live epic's diff
- [ ] `task_preflight.check_scope`: call it BEFORE the deployable-surface handoff; a hit is `HANDOFF` to the STORY door (cut `claude/<KEY>-<slug>` off the epic), never to `/cicd-push-e2e`
- [ ] `ship_preflight.check_lane`: same call before the light-gate return; a hit is exit 2, `VERDICT: BLOCKED`, the message names the epic branch, the overlapping files and the road
- [ ] Same-subsystem overlap without a file overlap → WARN (exit 1), not a block
- [ ] A clean run SAYS it checked: `N live epic branch(es) checked, no product-file overlap`
- [ ] Tests RED first in `test_ship_preflight.py` (SP-Q) and `test_task_preflight.py`, then GREEN, then revert-proved
- [ ] Replay the incident against the fixed gate: `ship_preflight.py --branch chore/AVCH-80-rolling-bugs` on the real repo must print BLOCKED naming `epic/AVCH-100…` and the six files
- [ ] The law in `git-policy.md` §Branch model: an in-flight epic freezes `main` for its scope; the epic absorbs `main` continuously through its own gated road; E2E runs on the epic (ruleset AVCH-119); `main` is reached once, by the operator's decision, after the epic is done and driven
- [ ] Door texts: `cicd-push-e2e.md` Step 1, `smh-close-task-merge-tree.md` Step 1, the branch-cut arms in `cicd-quick-dev.md` / `smh-quick-fix.md` / `smh-plan-task.md`
- [ ] SOP §7 + changelog row, same commit
