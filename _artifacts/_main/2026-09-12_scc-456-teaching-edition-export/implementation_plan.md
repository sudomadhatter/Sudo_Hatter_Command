### The operator's workflow, and the defect that breaks it

Ruled this session: the published edition exists so team members can read Mr. Hatter's workflow and
keep it current with `git pull`; they then add their own projects from the `sudo-project-skeleton`
repo. That model is sound end to end — projects are thin and read their law from the centre they sit
in, so a team member's project reads from *their* teaching-edition clone and nothing reaches back
into this workspace.

But the publish step is broken in a way that hits those readers directly. The exporter **refuses a
non-empty target** (`export-teaching-edition.ps1:244-247`) so that stale files cannot survive a
refresh invisibly. The consequence is that whoever publishes exports to a fresh folder and copies it
over the repo — and **a copy adds and overwrites but never removes.**

Measured: the published edition carries **84 files `main` has deleted**, including whole retired
subsystems.

### Why the branch is storage, not a pipeline stage

The branch holds exactly two things: the **engine** (exporter, manifest, `replacements/`, validator,
its 1,026-line test) and the **tutor** (`/smh-tour`, `/smh-training`, the `training-mode` rule and
its `.training-mode` sentinel).

The engine can move to `main` today with no consequence, because the manifest already excludes
`export-teaching-edition.ps1`, `teaching-edition/` and `test_teaching_edition.py` from its own
export — they were built never to ship. The tutor cannot: it must appear in the export, so today it
must exist in the source tree, and putting it on `main` would give the lobby two doors nobody there
uses and force every door-parity test to carry an exception.

So the tutor needs an **overlay**: files the export *adds* from a directory the lobby otherwise
ignores. The manifest already has the same machinery pointed the other way (`transforms` replaces an
exported file with one from `replacements/`), so this is one new block, not a new mechanism.

Once both move, the branch has nothing unique left in it, the 396-commit merge disappears
permanently, and the chain goes from three stages to two.

## Part B — the overlay, so the tutor ships without polluting the lobby

### B1 — the manifest block and the exporter support

```json
"_comment_overlay": "Teaching-only surfaces that do not exist in the source tree. Added AFTER the
copy pass and BEFORE substitutions, so they are sanitised like everything else. A declared overlay
whose source file is missing FAILS the export.",
"overlay": [
  { "path": ".agents/commands/smh-tour.md", "from": "overlay/smh-tour.md" }
]
```

Three properties, each of which gets a pin:

1. **A missing overlay source fails the export.** Same fail-closed direction as the anchors — a
   tutor that silently stops shipping is the defect this lane exists to end.
2. **An overlay may not overwrite a copied file.** If the source tree grows a file at an overlay
   path, that is a collision and the export refuses rather than guessing which wins.
3. **Overlays run before the substitution and leak passes**, never after — an overlay that skipped
   the leak scan would be a hole straight through the only guard this export has.

   ⚠️ **AUDIT FINDING 9 (baked, pre-mortem): copy-last is the natural implementation and it is the
   hole.** The obvious way to write an overlay is to copy it in at the end, so nothing can overwrite
   it — and the end is *after* `substitutions` and *after* the leak scan, which means the tutor
   files ship with whatever they happen to contain, unsanitised and unscanned, straight to a public
   repo. The ordering above is therefore a **pinned property, not a preference**, and
   `test_teaching_edition.py` gets a case that plants a leak literal in an overlay source and
   requires the export to fail. Collision (property 2) is what replaces copy-last as the protection
   against being overwritten.

## Part C — provenance, the publish door, and the staleness nag

### C1 — the provenance stamp

The export records nothing about its source. That is why eight days passed invisibly: staleness is
not merely unnoticed, it is **unmeasurable**. The exporter writes one file into the export root:

```
.teaching-edition-source
  source_commit: <40-char sha of the lobby HEAD at export time>
  source_date:   <ISO-8601>
  exported:      <ISO-8601>
```

It carries a sha and two dates and nothing else — no branch name, no author, no path — because this
file ships to a public repo and the leak scan applies to it like any other byte.

### C2 — `/smh-publish-teaching-edition`, the door that makes deletion real

This is the part that fixes what hurts the readers. The door, in order:

1. Refuse unless the lobby tree is clean and `HEAD` is pushed — a published snapshot of uncommitted
   work is unreproducible.
2. Export to a fresh scratch directory (the exporter's own refusal to write into a non-empty target
   is preserved, not worked around).

   ⚠️ **AUDIT FINDING 7 (baked): the scratch directory must be OUTSIDE the lobby.**
   `export-teaching-edition.ps1:241` refuses a target inside the source tree — *"Target must be
   outside the source tree to prevent recursive self-copy"* — and the published repo lives at
   `Projects/sudo-command-center`, which **is** inside it. So the export can never be written to
   its own destination, a repo-local `scratch/` is refused too, and the two-stage temp-then-publish
   shape is forced by the engine rather than chosen. The door uses the session scratchpad.

3. The leak scan runs inside the exporter and cannot be skipped. **Stop on any hit.**
4. In the published repo, clear the tracked tree and copy the export in. **This is the step that
   makes a deletion a deletion**, and it is why the six retired doors plus 78 other files leave the
   team's copy.

   ⚠️ **AUDIT FINDING 8 (baked): the clear is scoped to TRACKED paths, never a glob delete.**
   `git ls-files -z | xargs -0 rm -f` removes exactly what git knows about. A `rm -rf *` in that
   directory would also eat the reader's untracked files, and aimed one level wrong it eats `.git`
   and the history every team clone depends on. Tracked-only, enumerated by git, never by the shell.
5. Print the diff — adds, modifies and **deletes** counted separately — and stop for Mr. Hatter's
   eyes before anything is pushed. Publishing to a public repo stays a deliberate human act.
6. Commit on top (never force-push, never re-init) and open the PR.
7. Bump the lobby's submodule pointer in this lane.

⚠️ **AUDIT FINDING 3 (baked): a door lands on FIVE surfaces, and the plan declared two.** Measured
against a live door — `/smh-quick-dev` exists at `.agents/commands/`, `.agents/skills/`,
`.claude/skills/`, `.opencode/commands/` **and** `.roo/commands/`. The three launchers are generated
by `/smh-sync-agents`, but generated is not the same as undeclared: `test_command_surfaces.py`
iterates every door against every surface, so two-of-five lands red, and the review's drift check
reads three undeclared paths. All five are now in the Declared Change Set, and a sync run is part of
the build, not an afterthought. This is SCC-66's scar — *a rename orphans four caches* — arriving as
a creation rather than a rename.

### C3 — the staleness nag

A published snapshot does not need to match every commit; it needs to not rot for months. So this
reports, it does not block — a gate that fired on every lobby lane the moment `main` moved would be
switched off within a day.

`.agents/scripts/teaching_edition_staleness.py` reads `.teaching-edition-source` from the published
submodule, counts `git rev-list --count <source_commit>..origin/main`, and prints one line when that
exceeds a declared budget. Same contract as the three staleness reporters already running at
SessionStart (`check-repo-map-drift.ps1`, `check_maps.py --depth3-only`,
`record_map_changes.py --nag`): never blocks, fails open, silent when clean.

⚠️ **AUDIT FINDING 4 (baked): as first drafted this script would have shipped INERT.** Its only
caller was a row in `.claude/settings.json` — which is **sandbox-denied to every agent**, so the
plan was handing Mr. Hatter an action and landing a file that did nothing until he took it. A gate
nobody armed is a file, not a mechanism, and this house has the scar already
(`a-landed-fence-can-be-missing-from-the-working-tree`).

**It rides `.agents/hooks/session-start-context.sh` instead** — already registered at SessionStart,
inside `.agents/hooks/` which agents *can* write, and it already conditionally shells a Python
reporter (the flight-recorder `surface` block at its tail) so the shape is established rather than
invented. Arming is then part of this diff and provable by running the hook, and **no operator
action is required at all.**

**Assertions that prove Part C:** a planted literal (`dlohneiss`) in a source file makes the export
**fail**, seen red before the fix — this is the one assertion that matters most, because it is the
guard standing between the workspace and a public repo; a file deleted from the lobby is **absent**
from the published tree after a publish run (today it survives); an untracked file in the published
tree **survives** the clear (finding 8); `teaching_edition_staleness.py` prints `N commits behind`
for a stamped tree, prints the un-stamped case distinctly, and exits 0 in both; running
`session-start-context.sh` by hand prints the staleness line, which is what proves it is **armed**;
the published repo's first parent is unchanged after a publish (history preserved).
