# SCC-446 - epic doors: `epic_mode.py`, the kickoff ask, one mode line per door, two landing arms

**Ticket:** SCC-446 (Subtask of SCC-441) · **Branch:** `chore/SCC-446-epic-mode-doors`
**Repo:** `Sudo_Hatter_Command` (the lobby) · **Date:** 2026-09-10 · **review-runtime:** fan-out

## What this is

Agents must know which epic they are on from command output, never belief, and the mode must be
chosen once by the operator at kickoff. Today five doors each carry their own `for-each-ref`
query and read a `-quickdev` suffix nothing ever cut; `/cicd-close-story-merge-tree` has a
direct-push arm the epic ruleset refuses; `/cicd-e2e` asserts an epic branch exists, which is
false in trunk mode; and two hand-authored launchers describe steps that no longer exist. The
mode becomes one script, every branch-touching door prints its answer first, and the landing has
two arms.

Design record: [SCC-441 implementation_plan.md](../implementation_plan.md).
The law: `git-policy` § The epic's mode and § The landing (SCC-442, landed first).

## The pieces

### 1. `.agents/scripts/epic_mode.py` (NEW)

```text
epic_mode.py --repo <abs path>
```

One query, `git for-each-ref --format=%(refname:short) refs/remotes/origin/epic/*` (the caller
fetches first, as every door does today; the script makes no network call), through
`wf_common.git`. Output, two lines:

| Line 1 (the bare word first) | Line 2 (the landing cost) |
|---|---|
| `TRUNK` | `lands on main by a PR the operator merges; main's ruleset checks; E2E at that PR` |
| `FULL epic/<KEY>-epic-<N>-<slug>` | `lands by PR into <branch>; four checks; E2E on every landing` |
| `LIGHT epic/<KEY>-light-epic-<N>-<slug>` | `lands by PR into <branch>; two checks (Backend (Python), Frontend (Node.js)); E2E once at /cicd-push-e2e, or /cicd-e2e on demand` |
| `AMBIGUOUS` + the refs | exit 2; the doors already stop on more than one epic |

`LIGHT` is `-light-epic-` in the name, exactly the token the law and the ruleset read. Exit 0 for
the three modes; read the word. `--repo` is required and explicit.

`test_epic_mode.py` (NEW): `_pf_fixtures.make_repo(remote=True)` + `branch(..., push=True)`:
`epic/SCC-1-epic-2-x` → FULL; `epic/SCC-1-light-epic-2-x` → LIGHT; none → TRUNK; two → AMBIGUOUS
exit 2; the cost line per mode; a local-only epic head is NOT a mode (origin decides). Seen RED
(script absent) then GREEN. `run_all.py` count +1. `.agents/scripts/INDEX.md` row and paragraph.

### 2. `/cicd-create-epic-sprint` asks FULL or LIGHT

`.agents/commands/cicd-create-epic-sprint.md:100-127`. The question becomes:

> **Is this epic FULL, LIGHT, or does this project run TRUNK?** *FULL* — every story lands by PR
> into the epic under the four-check gate, E2E on every landing. *LIGHT* — every story lands by PR
> into the epic under the two fast checks; E2E once at `/cicd-push-e2e`, or on demand. For a
> project not in production, or an epic of UI and docs. *TRUNK* — no epic branch is cut.

`TRUNK`). The two-numbers law (128-137) gains one sentence: the mode token sits between the key
and the sprint number, and `epic/` still comes first. The forced delete at line 280 that
`test_guard_branch_delete.py:253-254` keys on is untouched (its line number may shift; the fenced
