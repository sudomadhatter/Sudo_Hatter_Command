## What this is

words have to exist before any door can point at them. Today the rule names three epic modes, one

### 2. `git-policy.md` - the mode section is rewritten as FULL / LIGHT / TRUNK

`.agents/rules/git-policy.md:72-131`. The three bullets become:

- **FULL** (`epic/<KEY>-epic-<N>-<slug>`): every story lands by PR into the epic under the full
  gate, the four checks, E2E on every landing. Reaches `main` once through `/cicd-push-e2e`.
- **LIGHT** (`epic/<KEY>-light-epic-<N>-<slug>`): every story lands by PR into the epic under the
  two fast checks (Backend (Python), Frontend (Node.js)); the two E2E jobs skip on the server
  because the PR base carries `-light-epic-`. E2E runs once at `/cicd-push-e2e`, or on demand
  through `/cicd-e2e`. For a project not in production, or an epic whose landings are UI and docs.
- **TRUNK**: unchanged.

The direct-push bullet at lines 83-84 is deleted. The switch fence at lines 90-96 reads the token:

```bash
cd "$PROJECT_ROOT" && git for-each-ref --format='%(refname:short)' 'refs/remotes/origin/epic/*'
# epic/<KEY>-epic-<N>-<slug>        -> FULL:  PR into the epic, four checks, E2E every landing
# epic/<KEY>-light-epic-<N>-<slug>  -> LIGHT: PR into the epic, two checks, E2E once at /cicd-push-e2e
# NOTHING                            -> TRUNK: cut from origin/main, land on main by PR
```

Line 121 "In the two epic modes" becomes "In FULL and LIGHT mode". The trunk sub-blocks (write
gate, local merge guard, board files, the `claude/*` invariant) and the SCC-416 incident block stay
word for word. One sentence is added under the switch: the mode is chosen once by the operator at
kickoff; no door prompts to cut a light epic mid-flight.

### 4. `git-policy.md` - the landing is the PR road

`.agents/rules/git-policy.md:371-423`. The fenced sequence at 377-381 (`git push origin
HEAD:epic/…`) becomes the PR road for FULL and LIGHT alike:

```bash
git fetch origin epic/<JIRA-KEY>-<slug>
git merge origin/epic/<JIRA-KEY>-<slug>          # absorb it INSIDE the worktree
git push origin claude/<JIRA-KEY>-<story-slug>   # the PR's head — the one sanctioned push of it
gh pr create --base epic/<JIRA-KEY>-<slug> --head claude/<JIRA-KEY>-<story-slug> --fill
gh pr checks --watch                             # the epic's required checks, per its mode
gh pr merge --merge                              # the door's invocation IS the sign-off for an EPIC landing
```

Lines 383-385 ("Do NOT push the story branch itself") are rewritten to what lines 116-119 already
say: the story branch reaches origin as the head of its own landing PR or through `/cicd-park`,
and the close-out prunes it. The invariant paragraph (387-396) keeps its meaning with one added
clause: "or the head of an open landing PR". The trunk block (408-423) is unchanged.
