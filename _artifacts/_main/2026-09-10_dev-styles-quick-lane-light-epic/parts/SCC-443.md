# SCC-443 - scope check: a line, not a feeling

**Ticket:** SCC-443 (Subtask of SCC-441) · **Branch:** `chore/SCC-443-scope-check`
**Repo:** `Sudo_Hatter_Command` (the lobby) · **Date:** 2026-09-10 · **review-runtime:** fan-out

## What this is

The quick lane needs a line or it becomes the default because it is faster. Today the only
written list is prose in `/cicd-quick-dev` Step 1.5 ("auth/tenancy walls, payments, PII, DB
schema or security rules, a cross-boundary contract") and `lane_qualify.py` judges size, not
risk. This lane writes the list as a rule, gives it a script that answers from paths, and
defines the stop: **soft**. The agent stops, prints what overlaps and why it matters, and only
the operator's word moves it past that point. No agent override exists; the script never asks.

Design record: [SCC-441 implementation_plan.md](../2026-09-10_dev-styles-quick-lane-light-epic/implementation_plan.md).

## The pieces

### 1. `.agents/rules/critical-surfaces.md` (NEW)

An on-demand rule (`trigger: model_decision`, triggers: quick lane, quick-dev, scope check,
critical surface). Five surfaces, one reason each:

| Surface | Why the quick lane may not touch it |
|---|---|
| Auth and session | a wrong line here is every user's account |
| Billing, entitlement, cost caps | a wrong line here is revenue or a runaway bill |
| Security rules and data topology | Firestore and Storage rules are the last wall; the constitution already says ask first |
| FAA-facing answers | the retrieval and grounding pipeline is the product's credibility; a regression ships wrong regulatory guidance |
| CI and the gates | a workflow or hook edit changes what "green" means for everyone; the constitution already says ask first |

And the **map format**: each repo declares its own paths in `<repo>/.agents/critical-surfaces.json`:

```json
{
  "surfaces": {
    "auth":    {"why": "…", "paths": ["backend/middleware/auth.py", "frontend/src/contexts/AuthContext.tsx"]},
    "billing": {"why": "…", "paths": ["backend/routers/entitlement.py", "backend/services/cost_meter.py"]},
    "rules":   {"why": "…", "paths": ["firebase/firestore.rules", "firebase/storage.rules", "firebase.json"]},
    "answers": {"why": "…", "paths": ["backend/agents/specialist/", "backend/tools/librarian.py"]},
    "ci":      {"why": "…", "paths": [".github/"]}
  }
}
```

A path ending in `/` is a prefix; anything else is an exact repo-relative file. That is
`classify_changes.py`'s convention (`.github/scripts/classify_changes.py:38-52` in AviationChat)
and `sop_currency._SURFACES`'s, and it keeps `backend-notes/` from matching `backend`.

**Project law stays in the project** (`project-law.md`): the lobby's script reads the map; it does
not carry AviationChat's paths. AviationChat's map and the skeleton's placeholder map are rows on
AVCH-152 (the project lane), and the rule says so.

### 3. `.agents/scripts/scope_check.py` (NEW)

Modeled on `lane_qualify.py` (the qualify script `/smh-quick-fix` runs today) and
`sop_currency.py`; stdlib only, ASCII output.

```text
scope_check.py --repo <abs path> (--paths P [P ...] | --diff <base>)
```

- `--repo` is required and explicit, never the cwd (`lane_qualify.py:40-43` records why).
- `--paths` is the planned set (Step 1). `--diff <base>` is the real diff (the eject tripwire),
  read through `wf_common.changed_since_fork(repo, "HEAD", base)` so it is the merge-base diff,
  never a two-dot diff (`risk_seam.py:39-42` names the two-dot mistake as the expensive one).
- **Line 1 is the verdict as a bare word**, `CLEAR` or `OVERLAP`, then one line per overlap:
  `<path>  <surface>: <why>`. Read the word, not the exit code (`lane_qualify.py:24-27`).
- Exit `0` CLEAR · `3` OVERLAP · `2` the check could not run: empty `--paths`, a `--diff` whose
  git call failed, or a map file that does not parse. **Silence is unknown scope, never clear**
  (`lane_qualify.py:38-40`; the same tripwire `/smh-self-audit` names).
- Map resolution: `<repo>/.agents/critical-surfaces.json` if present; otherwise a built-in generic
  set (`.github/`, `*.rules`, `firebase.json`, `.agents/hooks/`, `.agents/scripts/git-hooks/`, and
  path fragments `auth`, `billing`, `payment`, `entitlement`, `session`) and a printed line
  `MAP: none for <repo> - generic surfaces only`, so an unmapped repo is loud, not silent.
- It never prompts, never reads the operator's answer, never writes anything.

### 4. `.agents/scripts/tests/test_scope_check.py` (NEW)

### 5. The wire-in, written here for SCC-444 and SCC-445 to cite

A section in the rule:

- **Step 1 of both quick lanes:** `python3 .agents/scripts/scope_check.py --repo "$REPO" --paths
  <the planned set>`. `CLEAR` → print the line and continue. `OVERLAP` → **stop**; print the
  overlap lines; say in one sentence what it would take to do this in the full lane; wait. The
  only thing that moves the lane past this point is the operator's word in this turn, quoted
  verbatim into the plan as `Scope override (<date>): "<his words>"`. "ok", "continue", "go ahead"
  are not it; the literal `approved` on the plan is not it either, because the plan has not been
  written yet.
- **The eject tripwire** (the close-out's Step 3.5 in the lobby, the pre-landing check in a
  project): the same call with `--diff origin/main` (Task lane) or `--diff origin/epic/<…>` (story
  lane). An `OVERLAP` the plan carries no override for **ejects** to the full lane and re-arms the
  plan-first gate. An overlap the plan does carry an override for is printed and passed.
