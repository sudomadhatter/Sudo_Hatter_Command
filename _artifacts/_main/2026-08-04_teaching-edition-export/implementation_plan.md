# Teaching Edition — Implementation Plan

**Branch:** `claude/teaching-edition` (off `main_debug`, clean tree at `b9e6a80`)
**Goal:** publish a shareable **pair** of repos — a teaching command center and a teaching project
skeleton — that a stranger can clone, key up, and learn the sudo system from, without ever touching
Daniel's personal layer. The pair is **generated by a script**, never hand-maintained, so it cannot
drift and cannot leak.

## Decisions already made (operator)

1. **Separate repos**, not a training layer bolted onto the live ones.
2. **Full 6-stop tour**, including running a real story end-to-end.
3. **Source = both** `Sudo_Hatter_Command` (lobby) **and** `Projects/Fresh_Workspace_BMAD` (skeleton).

## The core design: export, don't fork

A hand-maintained fork goes stale silently — the same failure already recorded for the per-project
autopilot engines. So the deliverable is an **export script + two manifests**. Improve a command in
the live repo, re-run the export, push. The manifest *is* the privacy audit: reviewed once, not
re-decided on every push.

## Phase 2 — the `.env` pair

- **New** `.env.example` at the **lobby** root — system keys only: `GITHUB_PAT_CLASSIC`,
  `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY` (deepseek lane), `TELEGRAM_BOT_TOKEN`/`CHAT_ID`,
  `SENTRY_AUTH_TOKEN`. Tiered **required / optional-per-feature**, each key with a one-line
  "where you get this". Confirmed `.env.example` is **not** caught by `.gitignore`.
- **Extend** [Fresh's existing `.env.example`](../../../Projects/Fresh_Workspace_BMAD/.env.example) —
  keeps its app keys, gains the same tiering + source links.
- **New** `.agents/scripts/export-env-example.ps1` — regenerates the lobby example from the real
  `.env`, **key names only, values stripped**. Cannot leak; cannot drift.

## Phase 3 — the toggle

- **New** [`.agents/rules/training-mode.md`](../../../.agents/rules/training-mode.md) — floor-tier
  when active. Overrides `operator-profile`; explain-before-execute; define each term on first use;
  after every command state what happened and what's next; treat the first `approved` gate as a
  teaching moment rather than friction.
- **Toggle = a `.training-mode` sentinel file at repo root**, not an env var — identical across all
  four surfaces (Claude / opencode / Antigravity / Codex), visible, greppable.
- **New** `.agents/commands/training.md` — `/training on|off`. States plainly that floor rules load
  at session start, so the change takes effect next session.
- Ships **present** in the teaching edition: a newcomer is in tutor mode from reply one.

## Phase 4 — `/sudo-tour` (6 stops)

**New** `.agents/commands/sudo-tour.md` + `.agents/skills/sudo-tour/SKILL.md`.

| Stop | Covers |
|---|---|
| 0 | What this system is + the two rules above every command |
| 1 | Keys in and verified (both `.env.example` files) |
| 2 | Clone the skeleton → `gh repo create` → first push → standing on `main_debug`, and **why `main` is a trap** (§7) |
| 3 | Idea → backlog: `bmad-brainstorming` → product-brief → PRD → architecture → epics/stories → `/sudo-create-epic-sprint` + risk scoring |
| 4 | **Run ①②③ live** on a seeded, deliberately tiny first story (a health-check endpoint) whose red phase is honestly red |
| 5 | The safety net that was running underneath + the ship gate; offer `/training off`. Autopilot gets a *mention*, not a stop — the engines have no canonical master and drift per project. |

Each stop ends at a checkpoint. **Resumable the autopilot way** — detects finished stops by their
marks, not a counter.

## Phase 6 — verification (the real gate)

1. `export-teaching-edition.ps1 -WhatIf` on both manifests; read the exclusion report.
2. Export to a scratch dir, then **leak-grep** the output for: `Daniel`, `dlohneiss`, `AviationChat`,
   `AGY`, `NEXgen`, `sudomadhatter`, and every key *value* from the live `.env`. **Any hit = FAIL.**
3. `python .agents/scripts/tests/run_all.py` still green (94 checks) — the export must not disturb
   the live tree.
4. Cold-read pass: open the exported lobby with fresh eyes and confirm nothing references a path
   that does not exist in the export.
5. Dry-run `/sudo-tour` stops 0–2 against the exported pair.
