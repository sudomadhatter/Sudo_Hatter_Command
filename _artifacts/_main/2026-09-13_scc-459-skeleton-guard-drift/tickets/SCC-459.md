# SCC-459 — the skeleton's guards are a hand-shortened copy, and nothing compares them

Why: `sudo-project-skeleton` is the repo we clone to start a project, and four of its git-hook
guards are hand-shortened copies of the lobby's — 364 executable lines against the lobby's 468,
while AviationChat tracks the lobby line-for-line at 462. Two of the four differ only in message
text. The other two carry real gaps: the backstop scans a narrower set of lanes (no `refs/heads/epic`
for a chore lane) and prints `git reset --hard`, the exact command the lobby bans by name after
SCC-180 destroyed three sessions' uncommitted work; the merge guard exits silently when it cannot
classify a merge source, so an unclassifiable merge is indistinguishable from an approved one. A
fifth defect is live in both projects: the guards print `.agents/rules/git-policy.md`, which neither
repo carries. None of this was caught because nothing in any repo compares the copies — the same
structural zero `test_twin_parity.py` was built to close.

## Plan
- [x] Initialise the skeleton submodule in the lane - the worktree ships it uninitialised
- [x] Pin all four defects RED against the current skeleton files before any repair
- [x] Part A - repair the four guards to the lobby's behaviour, each with a provenance header naming its source path and sha, and every `.agents/rules/` path reworded to name the centre's rule instead
- [x] Part B - bump the lobby's skeleton pointer (estimated 3 commits / 1,260 lines; the bump measured 8 commits / 2,096 insertions once the skeleton's own PRs landed)
- [x] Part C - one question, two postures: Jira = yes arms all three `*-ENFORCE` markers and the full enterprise system; Jira = no writes and arms nothing, which is already frictionless (`pre-push-main-approval.sh` exits 0 without the marker). Upgradable at any time
- [x] Part D - the setup asks two questions once (project name, Jira board) and wires the existing `rename-project.py`; on a "no" it says one sentence and drops it
- [x] The README becomes the brief for the agent that sets up the clone, with the two postures
- [x] Prove BOTH out of the box: a "no" clone pushes to `main` with no token and no prompt; a "yes" clone refuses a wrong-target merge and an untokened push
