`parallel_check.py` (SCC-56) backs `/cicd-parallel-check`, and the split of labour is the design: the **script** does the set math and the board writes, the **agent** reads the story files. That is not squeamishness about parsing — telling *"will modify"* from *"mentions"* is a judgment no parser wins. Across 139 AGY story files, 105 name source paths, 58 carry negative declarations, and only 29 have a `**Task**` checklist, so there is no field to read; story 19.1 names `google_llm.py:119` (a path inside the venv — a reference) and says *"NO `firestore_session.py` changes, that is 19.2 entirely"*, a negative declaration handing a file to a named sibling. Three things it derives rather than asks: the **repo** (the parent key's project prefix matched against each repo's own `.agents/jira.conf`, lobby included — so adding a project is zero edits, and two repos claiming one key is reported as the misconfiguration it is); the **base ref** for a story branch diff (**this** epic's `epic/*` branch by key, else `main` — never another epic's, which the retired board's "exactly one live epic branch is the normal case" fallback would have done, and AGY has two live right now); and **umbrella** children (a BMAD number that prefixes a sibling's — `12.3` over `12.3.4`/`12.3.7` — contains them rather than competing, found when the first live run had `AVCH-14` inherit all eight `story-12-3-*.md` files and lock against everything it contained). The approved set is the largest in which **every pair** is disjoint, computed exhaustively and deterministically because a stamp only means something if the same input gives the same set. Planning dirs never count as overlap; `docs/` deliberately does **not** join that list, since projects ship from it and over-excluding manufactures false greens. `stamp` **rewrites** `parallel-ok` across the whole epic rather than adding it — the strip is what makes an epic-scoped writer self-correcting where ①'s per-story one rotted. A grounded child with no touch-set is a hard refusal, never an assumed-empty set. `check` compares the stamped child list against the epic's current children: a set that has moved reads *"re-run me"*, which is the detector the sprint dependency map and the `Deferred` saved filter both lacked when they misled on 2026-08-09.

`split_sprint_status.py` ran the AGY migration 2026-08-03 (baseline `0752c437`): board 363,334 → 62,040 B in four staged applies, each `verify`d **byte-identical** by reconstructing the original from (board + history + manifest) — never peeking at the blob — and comparing against `git show <sha>:<path>`, the LF stream (the worktree stream varies by machine — `* text=auto`). Narrative now lives in `_bmad-output/history/<epic>/<key>.md` + `CHANGELOG.md`; the board carries bare `key: status`, a ≤120-char note on live rows only, enforced by `workflow_lint.check_board_note_budget` (a note on a `NO_NOTE_STATUSES` row is an ERROR; `story_status.py set` drops it on the flip automatically).

`gate_receipt.py` has no `--result` flag by design: it EXECUTES the gate and writes the receipt from the real exit code, so a verdict cannot be handed in. All flags precede `--`; everything after it is the gate command verbatim. Staleness compares **trees, not SHAs** — a branch that lands via a merge commit has a new HEAD and identical content, and calling that stale is how a hard gate earns a permanent `--advisory`.

`workflow_lint.py --staged [--fix]` is the **pre-commit encoding gate** (Wave 5): staged files only, encoding only, so it stays fast enough not to get disabled. Install with `git-hooks/install-encoding-hook.ps1 [-All]`. It resolves the hook dir from **`core.hooksPath`** first — the lobby, AGY and Fresh all set it to `.githooks`, so writing to `.git/hooks` installs a file git never reads; the first version of this installer did exactly that and reported success in three of four repos. It refuses to clobber a foreign `pre-commit` hook, and `scripts/git-hooks/DISABLE` (untracked) is the kill switch. `--fix` repairs only *unambiguous* cp1252 round-trips; everything less certain is reported, never rewritten.

**Every hook probes `python3 -> python -> py`, in that order** (aligned SCC-49). `pre-commit-encoding.sh` used to do `PY=$(command -v python || command -v python3) || exit 0`: it never tried `py`, so on a box with only the Windows launcher the substitution failed and the gate **exited 0 - armed in name, checking nothing, silently**, which VS Code's hidden hook output would have kept invisible forever. `.githooks/post-commit` had the same `python`-first order. Both now match `sop-currency.sh`, and the two armed gates ANNOUNCE a skip rather than taking it mutely. `test_jira_feed.py` guards the contract textually (the suite cannot execute a `.sh` on the PC) - reading CODE only, since the fix's own comment quotes the broken line and a raw grep would flag the fix as the defect.

`git-hooks/post-commit-jira-start.sh` (SCC-113) is the **second** `post-commit` recorder, and it exists because four transition seams wrote `Done` while exactly one wrote `In Progress` — the BMAD story lane — so on a board whose every non-epic ticket is a `Task`, nothing in the command centre was ever visible in flight. The trigger is deliberately **not** a command: `/smh-quick-dev` is not always run, and a fix that depends on remembering to run it re-creates the defect, so the signal is the first commit on a `chore/ · claude/ · epic/` branch — whatever route got there, a bare `git commit` included. It had to be `post-commit` and not the armed `commit-msg` gate, whose own header forbids growing it (*"a live 'does AVCH-57 exist?' call would put a network round-trip on every commit and would fail closed on a plane"*); `post-commit` carries the opposite contract — sealed commit, every error swallowed — so a network call is safe there and **never** blocks. Three properties are what make it cheap enough to leave armed, and all three are executed against a real git repo in `tests/test_jira_start_hook.py`: a marker under `--absolute-git-dir` short-circuits every later commit **before** any network call (one exchange per branch, ever — and the exchange is *three* acli round-trips, `view` → `transition` → the read-back, which is worth stating precisely because round-trip cost is the entire argument for `post-commit` over `commit-msg`); the marker is written **only on a SETTLED result** — moved, or already there — so an offline commit, a refusal, *and* a not-yet-startable status (`Blocking`, `In Review`, `Deferred`, which exit 3) all retry on the next commit rather than silencing the ticket forever; and the marker is named for the **branch**, not the key — a key-named one suppresses a second lane carrying the same key, which is exactly what a `Bug`-reopened ticket gets, and it was caught by the `claude/`/`epic/` cases failing for that reason instead of the one they were written for. The key comes from the branch matched against this repo's own `jira.conf`, so another project's key is ignored rather than mis-filed.

A file that legitimately **carries** those bytes as data — the detector's own constants, its fixtures, a doc quoting them — declares `wf-lint: allow-encoding-literals` and is skipped. Without it the gate blocks every commit that touches the gate.

`jira_feed.py` (SCC-49) is the only script here that WRITES to something outside the repo, so both of its write paths end by reading the ticket back: an `acli` call that exits 0 while recording nothing is indistinguishable from one that worked, and that is precisely the failure a prose instruction cannot catch. It renders, never invents — the story outline comes out of the story file's `## Story` block and `## Acceptance Criteria` list, and a story missing either renders `(none found in the story file)` plus a stderr warning rather than something plausible. `devrecord` keeps **exactly one** Dev Record per ticket by finding the existing one and updating it in place: `/cicd-quick-dev` files a record when it closes its own branch and `/cicd-update-sprint-memory` files one when it closes the story, and stacking those buries the current one. Its content is FLAGS FIRST (`--decision` / `--pitfall` / `--followon`, passed by close-out straight out of Step 3's learning routing) with a walkthrough scrape underneath as a safety net — an empty bucket renders `(none recorded)` and warns, and `--strict` makes it a hard fail. It resolves a project WITHOUT requiring a sprint board, because the command centre deliberately has none and its chore tickets still need records. `acli` comes from `--acli` / `$ACLI_BIN` / PATH, which is what lets the test suite drive the whole post-and-verify path against a stub executable. The work-item type is **derived**, in ONE place (`work_type()`), never defaulted - a fixed default is how the whole board ended up `Task`. `Story` = BMAD sprint work (debug stories included); `Task` = workflow/IDE/rules/skills work under a grouping epic; `Epic` is never computed. The PARENT is never the tell - everything is parented, and a BMAD epic is indistinguishable in Jira from a grouping epic. Story takes THREE signals because none survives the board alone: the dotted number is true before the story file exists (backfilled rows), the `debug-` marker carries ids with no number of their own, the file catches the rest (`tea-16`). **`Bug` is never computed, and cleared in exactly one place** - it is a TEMPORARY flag meaning a Story or Task turned out to be broken, raised by an audit that traced a live bug back to the ticket that introduced it or by the operator by hand, carrying the same number and file as before, so a rule that 'corrects' it mid-flight erases the only signal that the work is broken. `devrecord --closing` puts it back to `Story` **or `Task`** at close-out - whichever `work_type()` says the ticket is - because that is the one moment anything can know the fix landed; the bulk `audit` cannot tell 'still broken' from 'fixed', so it reports Bugs and moves on. Restoring only to `Story` (SCC-49's first cut) stranded every flagged **Task** as a permanent Bug, since nothing else in the system can clear one; fixed in SCC-53. `audit [--apply]` reports and migrates a whole board, reading each ticket back. Model + the AVCH worked example: `.agents/rules/jira.md` SS Work-item types.

**The RAISE half (SCC-54)** is two verbs, and they are two on purpose. `trace --path <file>[:LINE]` reads git only — `blame` on an exact line (the strong signal: the commit that wrote *that* line), `git log --no-merges` on the file (the weak one: worked nearby) — and ranks the tickets whose commit subjects carry a key, filtered to the project(s) in this repo's `.agents/jira.conf` so commit prose saying "unlike AVCH-13" cannot nominate a ticket this repo could not close. `--no-merges` because a `--no-ff` merge subject repeats its branch's key and would double-weight whichever ticket merged last for no added information. It has **no board path at all** — a deliberately broken `--acli` cannot make it fail. `flag --key <K> --reason "..."` writes: `Story|Task -> Bug`, `Done -> To Do`, and a **Bug flag** comment carrying the reason, the evidence and *what the ticket was*, each read back. It is idempotent (two testers, one bug, no fight), refuses an `Epic`, and moves the status **only out of `Done`** — a ticket `In Progress` was never finished, and reopening it would erase real state to say what the type already says. **`flag` takes `--key` and only `--key`, never a trace result:** "which ticket last touched this line" is not "which ticket introduced this bug", and a wrong flip pulls an innocent ticket out of `Done` with no undo. `/cicd-live-testing-team` Step 3.5 is the wired entry point — it already files a bug doc per symptom with the fix-direction paths `trace` needs — and it stops for the operator between the two verbs.

⚠️ **The defect SCC-54 found underneath itself:** `--fields` on `acli workitem view` is a **whitelist**, and `issuetype` was not on the list `view_fields()` sent. Every type read in the file goes through there, so on the live board `have` came back `""` — `devrecord --closing` never saw a `Bug` and therefore **never cleared one**, and `audit --apply` reports FAILED on every conversion that in fact succeeded. It passed green for two tickets because the test stub returned the whole shape no matter what was asked for. **A stub more generous than the tool it stands in for tests nothing**; the stub now enforces the whitelist, with a positive control asserting it is still strict.

`task_preflight.py` (SCC-49) backs `/smh-close-task-merge-tree`, the **Task** lane's close-out — the half BMAD has no answer for, since `/cicd-update-sprint-memory` needs a sprint board, a story file and an epic branch that task work does not have. Like `jira_feed.py` it resolves the repo **without** a board. The one check that earns the script is `LANE`, because the only thing making this command cheaper than `/cicd-push-e2e` is skipping the E2E suite, and the only honest justification — *nothing that deploys changed* — is exactly the claim an agent audits worst about its own work. So it is derived, twice over: `deploy_surface()` asks whether the repo **has** `backend/ · frontend/ · firebase/ · functions/ · mobile/ · .github/` at all (empty ⇒ the command centre, where `git-policy.md` says there is no E2E suite and never will be, so nothing is being skipped), and the diff-vs-`origin/main` asks whether **this** change reached one. Touched ⇒ `HANDOFF`, hard exit 2, `/cicd-push-e2e` — **no override flag, deliberately**. It also refuses `epic/`, `claude/` and `incident/` branches **by name, citing the command that IS right**, and treats a missing `_artifacts/` tree as an ERROR rather than "nothing to check" — absence of the tree is the strongest evidence the walkthrough was never written, and warning there is how the check would go quiet on the one repo that needed it. It reads and reports only: the merge, the transition and the branch delete stay in the command, where a human is watching the output.

`sop_currency.py` is the **second armed commit-msg gate** (SCC-31, 2026-08-08), running after the Jira gate from the same `.githooks/commit-msg` shim — note that shim now *calls and checks* rather than `exec`ing, since an `exec` replaces the process and would have made any second gate dead code. It rejects a commit that changes a **usage surface** (`commands/*.md` · `rules/*.md` · `scripts/*.py|*.ps1` · `git-hooks/` · `.githooks/` · root `AGENTS.md`) without staging `docs/_scc_sops_prds/workflows_testing_SOP.md`. Exempt: `INDEX.md` churn, `reference/`, `templates/`, `skills/`, `workflows/`, `_artifacts/`, its own tests — a gate that fires on mechanical churn gets opted out of reflexively. Opt out per-commit with `[sop-ok]` (logged in git forever); disarm by deleting `git-hooks/SOP-ENFORCE`; it no-ops in any repo without the doc. Law → `.agents/rules/sop-currency.md`. It checks **co-occurrence, not content**: no program can judge whether the doc edit was right, only that the author looked while the context was still in their head.

Tests: **`python3 .agents/scripts/tests/run_all.py`** (262 cases across 8 files, ~10 s, stdlib only, no pytest; files are auto-discovered, so a new `test_*.py` joins with no wiring). **⚠ Two machines, two spellings:** the Mac has **only `python3`** (no bare `python`, script or login shell); a python.org install on the PC has **only `python`**. Docs here are written `python3` — on the PC, drop the `3`. **Never hardcode either name in a script or hook** — probe `python3 → python → py`, as `git-hooks/sop-currency.sh` does; that is what makes a gate work on both boxes untouched. One test file per script. Each script is covered by the defect that motivated it, plus a positive control — a checker that reports nothing looks identical whether it is clean or dead, and a checker that reports *everything* gets muted. Both failures are represented.
