# scripts — INDEX

Maintenance scripts (MASTER here): `check_maps.py` (drift linter), `generate_repo_map.py` (repo-map generator), `sync-agents.ps1` (toolkit sync), `new-project.ps1` (workspace scaffolder), `generate_doc_graph.py` (doc graph). Mirrored to project vendored copies via `/sync-agents`.

**Workflow-enforcement scripts** (Wave 1, 2026-08-03) — these turn checklist prose into executable checks, so a command can say "run the check" instead of asking an agent to hold eight invariants in its head. Stdlib-only Python 3.11, no `yq`/`jq`.

| Script | Answers | Typical call |
|---|---|---|
| `wf_common.py` | shared paths, board parsing, drift detection, git helpers | (imported, not run) |
| `workflow_lint.py` | is the toolkit + a project self-consistent? | `workflow_lint.py --project AGY_AVIATIONCHAT` |
| `story_status.py` | do a story's TWO status surfaces agree — and flip both atomically | `story_status.py set 21.8b done` |

`split_sprint_status.py` ran the AGY migration 2026-08-03 (baseline `0752c437`): board 363,334 → 62,040 B in four staged applies, each `verify`d **byte-identical** by reconstructing the original from (board + history + manifest) — never peeking at the blob — and comparing against `git show <sha>:<path>`, the LF stream (the worktree stream varies by machine — `* text=auto`). Narrative now lives in `_bmad-output/history/<epic>/<key>.md` + `CHANGELOG.md`; the board carries bare `key: status`, a ≤120-char note on live rows only, enforced by `workflow_lint.check_board_note_budget` (a note on a `NO_NOTE_STATUSES` row is an ERROR; `story_status.py set` drops it on the flip automatically).

`gate_receipt.py` has no `--result` flag by design: it EXECUTES the gate and writes the receipt from the real exit code, so a verdict cannot be handed in. All flags precede `--`; everything after it is the gate command verbatim. Staleness compares **trees, not SHAs** — a branch that lands via a merge commit has a new HEAD and identical content, and calling that stale is how a hard gate earns a permanent `--advisory`.

`workflow_lint.py --staged [--fix]` is the **pre-commit encoding gate** (Wave 5): staged files only, encoding only, so it stays fast enough not to get disabled. Install with `git-hooks/install-encoding-hook.ps1 [-All]`. It resolves the hook dir from **`core.hooksPath`** first — the lobby, AGY and Fresh all set it to `.githooks`, so writing to `.git/hooks` installs a file git never reads; the first version of this installer did exactly that and reported success in three of four repos. It refuses to clobber a foreign `pre-commit` hook, and `scripts/git-hooks/DISABLE` (untracked) is the kill switch. `--fix` repairs only *unambiguous* cp1252 round-trips; everything less certain is reported, never rewritten.

**Every hook probes `python3 -> python -> py`, in that order** (aligned SCC-49). `pre-commit-encoding.sh` used to do `PY=$(command -v python || command -v python3) || exit 0`: it never tried `py`, so on a box with only the Windows launcher the substitution failed and the gate **exited 0 - armed in name, checking nothing, silently**, which VS Code's hidden hook output would have kept invisible forever. `.githooks/post-commit` had the same `python`-first order. Both now match `sop-currency.sh`, and the two armed gates ANNOUNCE a skip rather than taking it mutely. `test_jira_feed.py` guards the contract textually (the suite cannot execute a `.sh` on the PC) - reading CODE only, since the fix's own comment quotes the broken line and a raw grep would flag the fix as the defect.

A file that legitimately **carries** those bytes as data — the detector's own constants, its fixtures, a doc quoting them — declares `wf-lint: allow-encoding-literals` and is skipped. Without it the gate blocks every commit that touches the gate.

`jira_feed.py` (SCC-49) is the only script here that WRITES to something outside the repo, so both of its write paths end by reading the ticket back: an `acli` call that exits 0 while recording nothing is indistinguishable from one that worked, and that is precisely the failure a prose instruction cannot catch. It renders, never invents — the story outline comes out of the story file's `## Story` block and `## Acceptance Criteria` list, and a story missing either renders `(none found in the story file)` plus a stderr warning rather than something plausible. `devrecord` keeps **exactly one** Dev Record per ticket by finding the existing one and updating it in place: `/sudo-quick-dev` files a record when it closes its own branch and `/sudo-update-sprint-memory` files one when it closes the story, and stacking those buries the current one. Its content is FLAGS FIRST (`--decision` / `--pitfall` / `--followon`, passed by close-out straight out of Step 3's learning routing) with a walkthrough scrape underneath as a safety net — an empty bucket renders `(none recorded)` and warns, and `--strict` makes it a hard fail. It resolves a project WITHOUT requiring a sprint board, because the command centre deliberately has none and its chore tickets still need records. `acli` comes from `--acli` / `$ACLI_BIN` / PATH, which is what lets the test suite drive the whole post-and-verify path against a stub executable. The work-item type is **derived**, in ONE place (`work_type()`), never defaulted - a fixed default is how the whole board ended up `Task`. `Story` = BMAD sprint work (debug stories included); `Task` = workflow/IDE/rules/skills work under a grouping epic; `Epic` is never computed. The PARENT is never the tell - everything is parented, and a BMAD epic is indistinguishable in Jira from a grouping epic. Story takes THREE signals because none survives the board alone: the dotted number is true before the story file exists (backfilled rows), the `debug-` marker carries ids with no number of their own, the file catches the rest (`tea-16`). **`Bug` is never computed, and cleared in exactly one place** - it is the operator's TEMPORARY flag on a Story he found broken (type -> Bug, status -> To Do), carrying the same number and file as any Story, so a rule that 'corrects' it mid-flight erases his only signal that the story is broken. `devrecord --closing` puts it back to `Story` at close-out, because that is the one moment anything can know the fix landed; the bulk `audit` cannot tell 'still broken' from 'fixed', so it reports Bugs and moves on. `audit [--apply]` reports and migrates a whole board, reading each ticket back. Model + the AVCH worked example: `.agents/rules/jira.md` SS Work-item types.

`task_preflight.py` (SCC-49) backs `/close-task-merge-tree`, the **Task** lane's close-out — the half BMAD has no answer for, since `/sudo-update-sprint-memory` needs a sprint board, a story file and an epic branch that task work does not have. Like `jira_feed.py` it resolves the repo **without** a board. The one check that earns the script is `LANE`, because the only thing making this command cheaper than `/sudo-push-e2e` is skipping the E2E suite, and the only honest justification — *nothing that deploys changed* — is exactly the claim an agent audits worst about its own work. So it is derived, twice over: `deploy_surface()` asks whether the repo **has** `backend/ · frontend/ · firebase/ · functions/ · mobile/ · .github/` at all (empty ⇒ the command centre, where `git-policy.md` says there is no E2E suite and never will be, so nothing is being skipped), and the diff-vs-`origin/main` asks whether **this** change reached one. Touched ⇒ `HANDOFF`, hard exit 2, `/sudo-push-e2e` — **no override flag, deliberately**. It also refuses `epic/`, `claude/` and `incident/` branches **by name, citing the command that IS right**, and treats a missing `_artifacts/` tree as an ERROR rather than "nothing to check" — absence of the tree is the strongest evidence the walkthrough was never written, and warning there is how the check would go quiet on the one repo that needed it. It reads and reports only: the merge, the transition and the branch delete stay in the command, where a human is watching the output.

`sop_currency.py` is the **second armed commit-msg gate** (SCC-31, 2026-08-08), running after the Jira gate from the same `.githooks/commit-msg` shim — note that shim now *calls and checks* rather than `exec`ing, since an `exec` replaces the process and would have made any second gate dead code. It rejects a commit that changes a **usage surface** (`commands/*.md` · `rules/*.md` · `scripts/*.py|*.ps1` · `git-hooks/` · `.githooks/` · root `AGENTS.md`) without staging `_my_resources/_quick_reference/sudo_workflows_testing.md`. Exempt: `INDEX.md` churn, `reference/`, `templates/`, `skills/`, `workflows/`, `_artifacts/`, its own tests — a gate that fires on mechanical churn gets opted out of reflexively. Opt out per-commit with `[sop-ok]` (logged in git forever); disarm by deleting `git-hooks/SOP-ENFORCE`; it no-ops in any repo without the doc. Law → `.agents/rules/sop-currency.md`. It checks **co-occurrence, not content**: no program can judge whether the doc edit was right, only that the author looked while the context was still in their head.

Tests: **`python3 .agents/scripts/tests/run_all.py`** (237 cases across 8 files, ~10 s, stdlib only, no pytest; files are auto-discovered, so a new `test_*.py` joins with no wiring). **⚠ Two machines, two spellings:** the Mac has **only `python3`** (no bare `python`, script or login shell); a python.org install on the PC has **only `python`**. Docs here are written `python3` — on the PC, drop the `3`. **Never hardcode either name in a script or hook** — probe `python3 → python → py`, as `git-hooks/sop-currency.sh` does; that is what makes a gate work on both boxes untouched. One test file per script. Each script is covered by the defect that motivated it, plus a positive control — a checker that reports nothing looks identical whether it is clean or dead, and a checker that reports *everything* gets muted. Both failures are represented.
